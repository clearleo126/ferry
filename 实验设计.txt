【1. 一句话主张（冻结）】
面向 LLM 稀疏注意力持续 decode 的 host-staged 多 GPU 运行时：完整 KV 历史驻 pinned host，
GPU 只驻留每请求每层热工作集；miss 经 PCIe 以流水化批传输回填。系统以本地优先队列、
批处理跨 GPU 重分配、计算通信重叠为多卡控制面，在 4×3090（无 P2P、~12 GB/s）上
提升吞吐、降低通信放大、压低突发/偏斜尾延迟。
归因口径（W6/B1 后收紧，禁止笼统归因）：C 相对 B 的总倍数必须拆两段——
**执行引擎（批化执行 + 异步流水，B→D1：4 卡 5 次 = 1.54–1.57×）** 与
**窃取粒度（D1→C：4 卡 5 次 = 1.12–1.14×，且 C/D1 随 N 单调升 1.00→1.12）**。
因此论文主张分工：吞吐主张挂在执行引擎；**批粒度主张挂在窃取次数（↓≈175×）、
调度开销、以及"粒度价值随卡数上升"的扩展性证据**，不得再写成"批窃取带来 2× 吞吐"。

【2. 机制归因（W5 复核后定稿：开关已修正，M1 恢复为主贡献之一）】
三机制与**正确操作化**的消融开关，附跨卡实测（GPU2→GPU3，steady/16KB/32K）：
  M1 流水化批传输 = **独立 H2D 汇聚流 + event 依赖 → D2H/H2D 分向重叠**
     开关：`m1_p1`（P1 单流交替协议，D2H→H2D 同流严格交替，无分向重叠）
     → **端到端 1.85×**（43.83ms vs 23.74ms）；与 bench_comm 通道层比值 1.85×
       （19.15 vs 10.36 GB/s）**完全一致** → 通道层收益 1:1 传导到端到端。
     ⚠️ 原开关 `n_in_streams∈{1,2}` **不能隔离 M1**（实测 0.99–1.00×）：H2D 恒为
       独立流，n=1 时 channel 仍保留分向重叠 → 该开关只改 D2H 流数，与机制无关。
  M2 带宽感知批粒度：自适应批大小削减段数（开关 adaptive/固定粒度）
     → 段数 1024→267（0.26，中小总量）；端到端吞吐 ≈0.99–1.00× → **只报段数/尾延迟**
  M3 计算-通信重叠：event 依赖的 compute/copy 流水（开关 overlap/seq）
     → **端到端 1.91×**（45.27 vs 23.74ms）
  交互（重要）：**M1 与 M3 单独都近乎无效、必须同时存在**——
     M1 单独（P1+ov1 43.83 vs P1+ov0 45.50）= 1.04×；
     M3 单独（channel+ov0 45.27 vs P1+ov0 45.50）≈ 1.00×；
     两者同时（23.74 vs 45.50）= **1.92×**。机制解释：单流交替下传输流被占满，
     计算无处重叠；而分向重叠若无计算重叠也无从体现 → M1 是 M3 收益的使能条件。
  端到端分解（v4 定稿）：B 53.48ms → 批化 1.18× → 再靠 M1×M3 协同 1.92× → 完整 C
     23.74ms = 完整 2.25×。批粒度不与流水混为一谈（v1 的「batched 2.0×」经查是
     probe 的 **batched vs non-batched 单流**对照，既非双流也非 M1，已作废）。

【4. RQ】
RQ1 静态划分+大同步在到达偏斜/层间漂移/热缓存失配下是否劣化利用率与尾延迟？
    （R3/W2/W3 已证：是；imb 达 0.80（2 卡）/1.38（4 卡），A 在偏斜下扩展效率仅 1.042）

【5. 基线语义（锁定）】
A 静态+bulk-sync：全局 barrier（等全部任务到达）后一次性 bulk 迁移（经 host-staged 通道，
  禁止 D2D 绕过）+ 单 kernel。旧实现不等到达即传、或用 D2D 隐藏通信成本，均为伪影。
B 动态非批处理：逐段迁移 + 逐段 sync；段门控 = 段内最后任务已到达；单流。
C Ferry：自适应批 + 独立 H2D 汇聚流 + D2H 完成 event 依赖的分向流水 + event 依赖计算；
  批门控 = 批内最后任务已到达；
  在途窗口 pending_ahead。
D1/D2 公平对照（与 C 共用同一执行引擎，唯一差异 = 窃取粒度）：
  D1 = 每次窃取 1 个任务（one-steal，B 的粒度，但保留 C 的异步流水与批执行）；
  D2 = 每次窃取 victim 一半（steal-half，不按消费批截断，StealHalf 语义）。
  用途：把 C/B 总倍数拆为"执行引擎贡献（B→D1）"与"窃取粒度贡献（D1→C）"，
        并回应"为何不偷一半"（D2 vs C）。
门控总则：任何批/段在其最后任务到达前不得提交；出现负延迟即作废重调参。

【6. Workload B 参数（锁定，已实现）】
payload：low/med/high = 4KB/16KB/64KB。到达校准：tick 使 arrival_span ∈ [0.5,2]×
service_span；p50<0 作废。bursty = 64 任务同 tick 集中 + 行间指数静默；skewed = 帕累托。
tasks 64K–256K（总迁移量 64MB–4GB 覆盖饱和区）。
trace（新增，真实性列）：arrival=trace 读 FERRY_TRACE_CSV（默认 data/arxiv_arrivals.csv，
csv 为归一化 arrive_ticks；行数不足直接报错退出，禁止静默改分布）。转换器
tools/trace_to_arrivals.py 用整条 Mooncake trace 的 1180 个聚合桶当到达过程，
桶内 sum(input_length) 加权摊任务到 --tasks，ticks-per-span 对齐 steady 量级（32768）。
两种真实负载：arxiv（桶突发 2.89×）/ toolagent（3.19×），互为对照。

【7. Workload A（已实现已跨卡）】
QSA-style miss 流：多请求持续 decode，每 step 每层选 128–512 个 C4 block；步间 reuse≈66%；
层间独立；host pinned slab 存逻辑 KV，GPU 每(请求,层)固定热缓存（1×/2×/4× 档）；
miss 经批回填。执行器三模式 = kv_exec.cuh（A 步末同步 / B 逐 C4 / C 自适应批+重叠）。
跨卡结果见【0】。数据源是 host pinned slab（与设备无关），热缓存/kernel 驻 dst。

【8. 指标口径（锁定）】
延迟 = 完成时刻 − 到达时刻（event 级）；makespan = 首到达→末完成。
通信量 = 真实迁移字节；迁移段数 = 通信放大代理。
overlap ratio = 1 − T_pipe / (T_comm_alone + T_compute_alone)（R5 实现三项独立计时）。
Workload A 专属：hit rate、miss 字节/token、p50/p99 step。
扩展效率 = N 卡吞吐 / 单卡吞吐（4 卡窗口出）。

【9. 实验矩阵与消融开关】
开关：m1_p1{false,true} × adaptive{false,true} × overlap{seq,pipe}
      × n_in_streams{1,2} × queue{per-thread,wave} × 粒度{C4,固定页,固定1–4MB,自适应}
      其中 n_in_streams 仅表示 D2H 流数量，不作为 M1 消融；
输入：arrival{steady,bursty,skewed/mixed,trace} × hot{1,2,4}× × sparsity{4,16,64}KB × skew{bal,imb}
硬件：1（环回）/ 2（集群 PCIe4，已出）/ 4（vast PCIe3，已出；集群 4 卡待窗口）。
必做消融（R4）：去 M1（m1_p1=true，P1 单流交替、无独立 H2D 分向重叠）；
去 M2（adaptive=false，固定粒度）；去 M3（overlap=seq）；去本地优先（B 语义）。
公平基线（W6，run_multigpu 模式 3/4）：D1=one-steal、D2=steal-half，
与 C **共用同一执行引擎**（同自适应批、同流水、同在途窗口），唯一变量 = 窃取粒度；
用于把 C/B 总倍数拆成"引擎贡献"与"粒度贡献"。
建议：批大小曲线、hot 档位、per-thread vs wave。
不扫：语义模式、反压阈值、NVSHMEM、serving SLO、GNN/MoE 参数。

【10. 工程约束（七条，违反即死锁/假阴性/跨卡崩溃）】
1. 算通重叠只靠 event 依赖，不依赖跨 stream kernel 并发；队列+计算用单 kernel role-partition。
2. 迁移源必须驻留设备侧；host 数组不能作 HostStagedChannel 的 D2H 源
   （Workload A 例外：host pinned slab 本身就是源，通道对其只走 H2D 语义——由 slab_offset
   直供，不经过 D2H 段）。
3. 合成负载禁用随机字节→float（signaling NaN 位模式差异）；校验一律位级 memcmp。
4. 小总量会被自适应合并为单批；端到端 target_batches=8 保证流水窗。
5. CUDA event/stream 必须在 cudaSetDevice(src) 之后创建（跨设备 record 报
   invalid resource handle；单卡环回不暴露，跨卡必现）。
6. HostStagedChannel.submit() 会把上下文切到 src；调用方在 dst 流上启动计算 kernel 前
   必须 cudaSetDevice(dst)。
7. HostStagedChannel 析构会把上下文切到 src 销毁资源（现已恢复调用方设备）；
   任何「构造-使用-析构」块之后启动 kernel 前，仍必须显式 cudaSetDevice(dst)。
8. 通道 ring 深度必须 ≥ 在途窗口 pending_ahead + 2：event 依赖批持有在途批的
   h2d_done event，ring 浅于窗口时 slot 复用（event 被 re-record）发生在出队前，
   会等错批（伪同步）。run_ferry_abl 与 run_overlap_ratio 均按此建通道。

【11. 平台与执行策略】
共享集群：他人进程常驻（vLLM 驻留显存但 util=0% 时可用；util>0 或他人训练时禁用）。
监控线程 watch_gpu_window.sh 常驻（120s 轮询，日志 watch_gpu.log）。
⚠️ **同机邻居争用（2026-09-23 实测发现，影响全文集群数据口径）**：
  当 GPU0/1 被他人 vLLM 占用（util 100%）时，GPU2/3 的重复测量呈**双峰**：
  快模 ≈215–225ms、慢模 ≈250–272ms（差 15–25%），**与自身配置无关**
  （`--sat-mb=4.0` 参数未变，前 5 次全快模、后 2 次全转慢模）。
  机制：若邻居为 TP≥2，其每 token all-reduce 走 PCIe+host 通路，**与本系统
  host-staged 迁移争用同一 PCIe/内存带宽**。
  纪律（据 result/a5_b2_2card_20260923.md §5）：
  ① 集群 2 卡 A/B 比较**必须多重复并用均值**，单次差异 <25% 不可信；
  ② 这解释了集群 std 高而 vast 独占机 std 仅 1–8% —— **vast 干净数字不可被
     集群噪声数据替代**，两平台分工的必要性再获支持；
  ③ 若论文报集群 2 卡主数字，须声明"共享集群 + 同机邻居 PCIe 争用"，
     或择邻居空闲窗口重测（watch_gpu_window.sh 已挂）。
数字层级（v5）：环回=机制证据；集群 PCIe4 2 卡=绝对主数字；vast PCIe3 1–4 卡=扩展效率/
负载均衡/跨平台鲁棒性（集群 4 卡得窗口后再补一组绝对数字）。
**跨平台纪律**：换机器必须先跑 probe 三关（topo 无 NV#、P2P 全 0、bench_comm ratio）
+ 与集群参考对齐；绝对延迟/吞吐不得跨平台拼表，比值（C/A、C/B、M1、E）可跨平台。
租卡流程见「说明文档（大模型运行前必看）.md」（含验收清单、W3 命令、结果回收）。
预期差异：带宽越低 → T_comm 越大 → overlap ratio 越低（公式必然），M3 相对价值略升；
批大小饱和点可能右移，**批大小曲线必须两平台各报一条**。

【12. 风险与止损】
不写成 QSA/HiSparse 跟跑；不滑回「泛稀疏」或 GNN；不模块堆叠；不抢 Shetty 单卡队列；
不复现 8×256K 容量数字；Portable 相对 B 无稳定收益即停扩。
新增：
- R1 修正后 C 仍 ≤A → 先查通信占比（加 payload/tasks），不得改结论口径（已解除：R3 全正收益）。
- 窗口长期不可得（>2 周）→ 4 卡矩阵降级，主结论挂 2 卡 + 机制层倍数（已由 vast 平台解除）。
- **批窃取净收益偏低（W6 实测 ~1.13×）** → 不得靠它撑主结论；改为"引擎 1.81× + 粒度 1.13× +
  窃取次数 ↓165×"的三段式表述，若 4 卡重复后 C/D1 仍 ≈1.1× 则如实写"粒度收益有限"。
- **跨平台混用** → 已立纪律（见【11】）；任何跨平台表格必须区分绝对量与比值，且注明 PCIe 代数。
- 单次跑无方差 → 已列为必做（见【13】剩余 A），报均值±标准差或范围。

        更重要"成立，作为扩展性结论写入【1】归因口径。D2≈1.00 全程无收益。
      ✓ A5 **trace 前置条件复核（已闭合）**：synthetic.cuh 曾存在"trace 分支赋值被末尾 `t`
         覆盖（trace 分支 t 恒 0 → 全体同时到达）"的缺陷，已修（commit 584bbfb）。
         复核（集群 GPU2,3，33000 任务，单次）：arxiv C 227.16ms / C/A 1.48×；
         toolagent C 257.60ms / C/A 1.76×。**判据**：若到达仍被压成 0，两个不同 trace
         结果必须完全相同；实测显著不同 → 到达序列确实不同 → 修复生效。
         记录：results/a5_b2_2card_20260923.md §1。
         ⚠️ 单次跑（两 trace C 差 13% 落在环境噪声带内，见 §5 双峰噪声）；
         "两者不同"的结论成立，具体数值不作精确值用。
   A' 两卡补测（集群 GPU2,3，A5 + B1/B2；记录 results/a5_b2_2card_20260923.md）：
      ✓ B1 两卡 5 次复现：C/D1 = 1.14±0.08、C/D2 = 1.00±0.07
        ——与 vast 4 卡（1.12–1.14 / 1.00）**独立复现**，且卡数不同 ⇒ 粒度结论稳。
      ⏳ B2 两卡 5 次：C/E = 0.986±0.066（bursty 0.952±0.107）→ **E ≈ C，无增益**。
        与模型 P2 方向一致（N=2 时 α 小、深队列 eff 被钳到 max_mb ⇒ E≡C），
        但**不构成 B2 增益的证实**；须 4 卡判定。
      ✗ P1（`--sat-mb` 扫 0.25/0.5/1/2/4MB，7 次/档）**在 N=2 未被证实**：
        参数确实生效（migr 147→137 单调降，批确实变大），但 makespan 五档
        228–240ms 统计不可区分（std 18–29 全重叠）→ **曲线是平的**。
        不得作为结论上报；须在 4 卡或更干净环境重测。
   B. 决策机制做实（决定论文新颖性，最高风险项）：
      ✓代码/⏳数据 B2 成本感知批粒度（W7）：**已实现（mode 5 = costaware-E）**，
        与 C 同引擎同窃取语义（按消费批窃取），唯一变量 = 批大小决策——C 用 NT 常量，
        E 用四路实时输入：① 消费卡积压 occ(g) + ② 源卡剩余 busiest_other(g)
        → 可见工作量；③ 在途窗口占用 inflight → 反压（可见量摊到在途槽）；
        ④ 通道饱和区 pol.saturation_mb（probe --bw 实测拐点，--sat-mb 可调）→
        吞吐下界（工作不足时不硬凑大批）。规则 eff = visible/(1+inflight)，
        夹到 [min(饱和点, 可见量), max_mb]。
        实现：multigpu.cuh mode 5 + MultiGpuCtx::busiest_other + mean_batch_tasks
        遥测（C≈常量 vs E 随相位变化 = 决策差异直接证据）；run_multigpu 输出
        costaware-E 行 + [B2] 汇总（C/E 比值 + 平均批 + p99 对照）。
        冒烟（GPU2 单卡环回，单次）：steady E 341.3 vs C 347.0ms（+1.7%）；
        bursty E 315.9 vs C 324.1ms（+2.5%），p99 310.2 vs 319.6——方向一致但
        噪声级，仅证明逻辑正确。**待验证：4 卡 × 5 次重复**（浅队列/争用下
        E 的动态决策才有区分度；判据 = C/E ≥1.05× 且 p99 显著改善，否则如实
        记录"该 regime 下自适应粒度无增益"，粒度主张退回 B1 的扩展性证据）。
        **这是 ICDCS/IPDPS 审稿最可能的击穿点，验证优先级最高。**
   C. LLM 场景闭环（决定故事是否成立）：
      C1 诚实前提：当前多卡实现中 payload 恒从 pool 拉，**窃取不增加传输字节**
         （B 与 C 迁移量相同）→ "迁移贵 ⇒ 控制批粒度"在 Workload B 上不成立；
         真正带 KV 迁移成本的是 Workload A 跨卡版。论文的 LLM 闭环须挂在 Workload A。
      C2 Workload A 跨卡拓扑叙事 + dest 来源说明（前缀亲和性 → 初始放置 → 热点失衡），
         否则审稿人会问"凭什么任务到达时就已预先分配好卡"。
      C3 并行结构假设写死：本文假设请求在卡间**分区（DP / PD 分离 replica）**，非张量并行
         切分；TP/PP 因 lockstep 天然均衡，不在范围（否则 imb 假设不成立）。

【14. 推荐叙事（冻结）】
「Shetty 等解决了单 GPU 上可线性化、有进度保证的有界并发队列；但 LLM 稀疏注意力的持续
decode 把任务变成 host 完整 KV 与 GPU 热工作集之间的 miss 回填：静态划分与大同步在到达
偏斜、层间 locality 漂移和细粒度 PCIe 往返下放大通信、抬高尾延迟。我们提出不依赖 P2P 的
host-staged 多 GPU 运行时：miss 回填由独立 H2D 汇聚流与 D2H 完成 event 实现分向重叠，
批粒度按待迁数据量自适应落在通道饱和区，计算再以 event 依赖与回填流水重叠。
已证（均为多次重复的 mean±std，不用单次值）：2 卡真实跨卡（集群 PCIe4）+ 4 卡（vast PCIe3）
控制面与扩展性。偏斜下静态划分 imb 达 0.80（2 卡）/1.38（4 卡），本设计以 ~100 次批窃取
拉回 0.017–0.050，窃取次数比单任务粒度低约两个数量级；4 卡偏斜档 C/A 1.47–1.60（±0.04–0.14），
C/B 1.72–1.87。**加卡收益几乎全部来自控制面**：强扩展 E(4)=1.395 而静态划分 A 仅 1.04×；
弱扩展 E_weak(4)=1.603（每卡效率 0.401，受单卡 host-staged 带宽约束）。
水位阈值跨 5× 范围仅改变 makespan 3.8%（鲁棒，非需精调的超参）。
跨两平台带宽相差 2× 时机制倍数保持（M1 1.85→1.90×，M1×M3 1.92→1.93×，T_compute 逐位一致、
T_comm 1.84×）→ 绝对数字平台相关、比值平台无关。
措辞纪律：C/B 总倍数=引擎贡献（4 卡 5 次 1.54–1.57×）+粒度贡献（1.12–1.14×，
且 C/D1 随 N 单调升 1.00→1.12），不得笼统归因"批窃取"；范围声明：卡间为分区（DP/PD-replica）而非 TP 切分；
集群 PCIe4 四卡绝对数字待窗口补齐。」

【15. 抽象模型（insight 收束 · 由【0】实测反推，非先验假设）】
15.1 记号与实测标定
  g    批字节 = **唯一决策变量**；p 单任务 payload（4/16/64KB，medium=16KB）
  B(g) host-staged 有效带宽，饱和型（probe --bw 实测，results/w3/bwscan.txt）：
       vast PCIe3（GB/s）：16KB→1.21 64KB→2.54 128KB→4.04 256KB→4.55
                           512KB→5.14 1MB→5.51 2MB→5.73 4MB→5.85 16MB→5.95
       集群 PCIe4：≥1MB 饱和，16MB→11.9（两平台 g* 同阶，纵轴 ≈2×）
  g*   饱和点 = B(g) 达渐近值 90% 的最小 g ≈ **0.7–1MB ≈ 64 任务 @16KB**
  W    在途窗口 pending_ahead = 4；Q_i 卡 i 队列长度；imb 完成数变异系数
  实测锚点：C 固定策略 mean batch = 254–256 任务 ≈ 4MB（= max_mb，符合预期）

15.2 核心耦合（insight 本体）
  CPU 窃取谱系（Cilk / StealHalf / BWoS）：迁移单位 = **指针**，成本 ≈0
    → 粒度只影响均衡质量，是**单目标**问题，故"偷一半"可以是普适答案。
  请求级 KV 迁移（Llumnix）：迁移成本高，但被数十秒 decode 摊薄
    → 粒度不是核心变量，"迁不迁/迁哪个"才是。
  **host-staged 多 GPU（本文 regime）：迁移单位 = 数据本身，且批粒度落在
  通道饱和曲线的陡峭段上** → 同一个 g 同时决定两件相反的事：
    ① 带宽效率 B(g)：g↑ → 单位字节成本↓（压向大批）
    ② 重分配响应粒度：g↓ → 才能细粒度纠偏、压低尾延迟（压向小批）
  ⇒ **一个决策变量、两个相反目标，且二者被硬件曲线耦合** = 本文问题本体。
    这是上述两个谱系都不面对的 regime，也是 Ferry 唯一可辩护的 novelty 落点。

15.3 代价模型（三项，符号方向由实测定，不是推演）
  makespan(g) ≈ V/(N·B(g))            [T1 传输：g↑ 则↓，g≥g* 后触底]
              + c_s · (V_mv/g)        [T2 重分配开销：窃取次数 ∝ 1/g，g↑ 则↓]
              + α · g                 [T3 纠偏量子/尾延迟：g↑ 则↑]
  V 总迁移字节；V_mv 需重分配的字节；c_s 单次窃取开销；α 失衡敏感度（∝imb、∝N）
  ⚠️ **T2 在当前 Workload B 实现中不是传输成本**：payload 恒从 pool 拉，窃取只搬
     任务 id，B 与 C 迁移字节相同（【0】实测 512.00MB 全等）。故 T2 = 全局锁争用 +
     重新取活延迟，**非带宽**。带 KV 迁移成本的 T2 要靠 Workload A 跨卡（见 C1）。
  T1、T2 同向递减，T3 递增 ⇒ **存在内部最优 g_opt**；又因 g≥g* 后 T1 触底、
  T3 仍线性增，故 **g_opt ≈ g***（模型的核心可验证预测）。

15.4 模型对已有实测的解释力（逐条对账，含不利数据）
  ① M2 端到端 ≈0.99–1.00× 但段数 1024→267：默认已运行在 4MB ≥ g*，**T1 已触底**
     → 吞吐无差异（符合），收益只体现在 T2（段数/往返）。模型解释了"M2 只主张
     段数不主张吞吐"这个原先只能描述、无法解释的边界。
  ② D2(steal-half) ≈ C（0.996–1.002）：victim/2 与消费批**都 ≥ g***，同在 T1 平台段
     且 T2 同量级 → 必然无差异。**这不是"偷一半没用"，而是"两者都已在饱和区"**，
     回应 StealHalf 的正确方式。
  ③ D1(one-steal) 差 1.12–1.14×：窃取粒度 1 任务 → T2 爆炸（17.5K vs ~100 次，
     ≈175×）。模型预测惩罚来自 T2 而非 T1 —— 与"迁移字节全等"的实测一致。
  ④ 平衡档 C/D1 仅 1.02–1.08：imb≈0 ⇒ α≈0 ⇒ T3≈0，且 V_mv≈0 ⇒ T2≈0
     → 粒度失去作用面。**模型给出"粒度收益条件于偏斜存在"的机制解释**。
  ⑤ C/D1 随 N 单调升 1.000→1.066→1.098→1.122：N↑ 使锁争用（c_s）与失衡（α）同增
     → T2、T3 权重上升 → 粒度决策价值上升。模型预测该曲线单调，实测单调。
  ⑥ 阈值 thr 跨 5× 仅变 3.8%：thr 只改**何时**触发窃取，不改 g → 不进入三项主项
     → 必然不敏感。模型解释了这个"负结果"为何是应然而非侥幸。
  ⑦ B2/E 单卡冒烟仅 +1.7–2.5%（噪声级）：单卡 imb=0.000（实测）⇒ α=0 ⇒ T3=0；
     且可见工作量巨大 ⇒ E 的 eff 被钳到 max_mb ⇒ E≈C（实测 mean batch 242.7 vs
     254.0，几乎同批）。**模型事先预测了这个"无增益"，故该冒烟结果支持模型而非反证。**
  作用域声明：本模型只刻画**控制面**（g 的选择）。M1/M3（分向重叠、算通重叠）属
  **数据面**，与 g 正交——这解释了为何 M1×M3 协同 1.92–1.93× 在两平台保持、
  且不随 g 策略变化。

15.5 可验证预测与反证条件（B2 四卡验证据此判读）
  P1 g_opt ≈ g*：`--sat-mb` 扫 0.5/1.0/2.0MB，E 的最优应落在 g* 附近而非端点。
     **反证**：若最优在 16MB 或在最小值端点 → T3 或 T1 的形状假设错，模型须改。
     ▸ **N=2 实测未证实（2026-09-23）**：0.25/0.5/1/2/4MB 五档 makespan
       228–240ms、std 18–29 全重叠，**曲线是平的**（参数确生效：migr 147→137）。
       判读：与"T3 在 N=2 权重过低、T1 已饱和"自洽，但**不能算证实**；
       P1 仍需 4 卡或更干净环境重测，且须先解决【11】的双峰邻居噪声。
  P2 E 优于 C 仅在 α>0 且队列浅：即 4 卡 × imbalanced × bursty（相位性浅队列）
     最明显；steady 深队列下 E→C。**反证**：若 balanced 档 E 也显著优 → T3 项
     不是失衡驱动，"纠偏量子"解释错。
     ▸ **N=2 初测与方向一致但无增益**：steady C/E 0.986±0.066、
       bursty 0.952±0.107（E 批小约 4%，p99 无一致改善）→ 支持"E→C"一侧，
       但增益侧未观察到，故不作证实。
  P3 增益随 N 上升（与 C/D1 同向）。**反证**：若 4 卡 E≈C 而 2 卡 E>C → 与 ⑤ 矛盾。
  诚实退路（已在 B 段写明）：若 P1–P3 均不成立且 C/E<1.05×，则如实记为
  "该 regime 内固定饱和区批粒度已接近最优"——**这本身是有价值的负结果**：
  它把贡献收敛为"给出 g_opt≈g* 的判据 + 证明粒度价值随 N/偏斜放大"，
  而非"又一个自适应启发式"。不得为凑增益而改口径。
