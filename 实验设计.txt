【1. 一句话主张（v11 重写：主语从"机制"换为"决策"）】
面向 LLM 稀疏注意力持续 decode 的 host-staged 多 GPU 运行时：完整 KV 历史驻 pinned host，
GPU 只驻留每请求每层热工作集；miss 经 PCIe 批传输回填（流水与算通重叠为**采用的标准
手段**，非本文主张，见【2】末段）。本文主张的是**该 regime 下的迁移决策**：在无 P2P、
D2H/H2D 共路、且所迁数据为对端当前步即需的约束下，**何时迁移值得、该迁什么内容**——
以成本×收益联合的值过滤（E）在 4×3090 上做到等性能下迁移字节 −30~65%、均衡质量更优，
并给出"决策价值 ∝ 记账保真度"的适用边界（pool-only 下失效，真实 payload 迁移下复活）。
⚠️ v11 旧版措辞（"系统以本地优先队列、批处理跨 GPU 重分配、计算通信重叠为多卡控制面，
提升吞吐…"）**作废**：该句把标准手段写成了贡献主语，MAST[ICDCS'25] 后不可用。
归因口径（W6/B1 后收紧，禁止笼统归因）：C 相对 B 的总倍数必须拆两段——
**执行引擎（批化执行 + 异步流水，B→D1：4 卡 5 次 = 1.54–1.57×）** 与
**窃取粒度（D1→C：4 卡 5 次 = 1.12–1.14×，且 C/D1 随 N 单调升 1.00→1.12）**。
因此论文主张分工：吞吐主张挂在执行引擎；**批粒度主张挂在窃取次数（↓≈175×）、
调度开销、以及"粒度价值随卡数上升"的扩展性证据**，不得再写成"批窃取带来 2× 吞吐"。
⚠️ **v11 修正（MAST 触发）**：上句"吞吐主张挂在执行引擎"仅为**归因口径**（数字归属），
**不再等于新颖性主张**——执行引擎 = M1×M3 = 标准手段，已退出创新点清单。
故本节拆分继续用于"说清加速来自哪里"（这本身是归因纪律上的贡献），但
**引擎那 1.55× 不得作为卖点**；论文的新颖性落点见卷首 v11 段四条。

【2. 机制归因（W5 复核后定稿；⚠️ v11：M1/M3 为标准手段，本节数据只作实现章节与
     "非加性测量发现"，**不得作为创新点主张** —— 详见卷首 v11 段与【3】）】
三机制与**正确操作化**的消融开关，附跨卡实测（GPU2→GPU3，steady/16KB/32K）：
  M1 流水化批传输 = **独立 H2D 汇聚流 + event 依赖 → D2H/H2D 分向重叠**
     开关：`m1_p1`（P1 单流交替协议，D2H→H2D 同流严格交替，无分向重叠）
     → **端到端 1.85×**（43.83ms vs 23.74ms）；与 bench_comm 通道层比值 1.85×
       （19.15 vs 10.36 GB/s）**完全一致** → 通道层收益 1:1 传导到端到端。
     ⚠️ 原开关 `n_in_streams∈{1,2}` **不能隔离 M1**（实测 0.99–1.00×）：H2D 恒为
       独立流，n=1 时 channel 仍保留分向重叠 → 该开关只改 D2H 流数，与机制无关。
  M2 带宽感知批粒度：自适应批大小削减段数（开关 adaptive/固定粒度）
     → 段数 1024→267（0.26，中小总量）；端到端吞吐 ≈0.99–1.00× → **只报段数/尾延迟**
  M3 计算-通信重叠：event 依赖的 compute/copy 流水（开关 overlap/seq）
     → **端到端 1.91×**（45.27 vs 23.74ms）
  交互（重要）：**M1 与 M3 单独都近乎无效、必须同时存在**——
     M1 单独（P1+ov1 43.83 vs P1+ov0 45.50）= 1.04×；
     M3 单独（channel+ov0 45.27 vs P1+ov0 45.50）≈ 1.00×；
     两者同时（23.74 vs 45.50）= **1.92×**。机制解释：单流交替下传输流被占满，
     计算无处重叠；而分向重叠若无计算重叠也无从体现 → M1 是 M3 收益的使能条件。
  端到端分解（v4 定稿）：B 53.48ms → 批化 1.18× → 再靠 M1×M3 协同 1.92× → 完整 C
     23.74ms = 完整 2.25×。批粒度不与流水混为一谈（v1 的「batched 2.0×」经查是
     probe 的 **batched vs non-batched 单流**对照，既非双流也非 M1，已作废）。
  ⚠️ **v11 写作口径（强制）**：本节全部数据保留且照报，但措辞必须是
     "我们在 host-staged 无 P2P 路径上**采用**分向重叠与算通重叠（标准手段，
     引 MAST[ICDCS'25]/CoCoNet/PipeMoE/Tutel），并**测量到二者在该 regime 下非加性**"。
     禁用动词："提出/设计/创新" + M1/M3。保留的科学内容 = **非加性发现本身**
     （单独各 ≈1.0×、联合 1.92×，机理 = 单流交替下传输流被占满使计算无处重叠），
     这是 regime 特有的观测，但只值一段，不值一个 section。

**HotPrefix / KVFlow 对位段（v12 新增；2026-10-05 核实）**：
  两篇均为**单实例（单卡 + CPU/host 外存）**工作，**均无跨卡迁移、无多卡控制面** —— 这是
  本项目与它们的切割线。但它们与本项目的**机制侧高度重叠**，必须在 related work 显式对位，
  否则审稿人会认为本文把"标准手段"当贡献（与 v11 对 MAST 的处理同理）：
  - **HotPrefix**（Proc. ACM Manag. Data 3(4), Article 250, 2025-09-23, DOI 10.1145/3749168；
    南京大学）三项：① 前缀树节点**热度动态追踪**；② **选择性准入**（GPU 逐出时只把高热度
    KV 留在 CPU 内存）；③ **热度提升**（周期性把高热度前缀从 CPU 升回 GPU），并配
    **I/O 与计算流水以掩盖传输开销**。SGLang 实现，vs vLLM(开启 prefix sharing) 最高 2.25×，
    vs SGLang 最高 2×。
  - **KVFlow**（NeurIPS 2025 poster；OpenReview 5Iw1nDtYmT；DOI 10.52202/085713-4208；
    UCSD+AWS）用 **Agent Step Graph + steps-to-execution** 做 KV 节点级细粒度逐出，并配
    **完全重叠的 KV 预取**（后台线程 CPU→GPU）。vs SGLang 分层 radix cache：单工作流
    最高 1.83×、多并发工作流最高 2.19×。

    ① **再证 v11 的新颖性边界判定**：这两篇说明"host↔GPU KV 传输 + I/O 与计算重叠"
       在**单实例**服务里已是标准手段 ⇒ 本文 M1/M3 不作贡献主张的口径正确，且有了
       更多先例（与 MAST/CoCoNet/PipeMoE 并列引用）。**贡献句禁止出现"重叠/流水"作主语。**
    ② **切割线收敛为一条**：两篇都在**单实例内**做"热度感知的 KV 驻留/逐出"（谁该留在
       快层），本文做**卡间**的"负载重分配 + 无 P2P host-staged 迁移成本决策"（谁该做、
       数据怎么搬）。热度/前缀组在本项目只是**dest 偏斜的来源**（C2），不是调度目标。
  - 建议写法：「热度感知的 KV 缓存调度已在单实例内被充分研究（HotPrefix、KVFlow、KVFlow
    类工作），其目标是在 GPU/CPU 分层间选择**哪些前缀值得驻留**；本文的问题在上一层——
    请求已在某卡排队/执行后，**该由哪张卡来做、搬过去的代价是否划算**，且卡间无 P2P、

【5. 基线语义（锁定）】
A 静态+bulk-sync：全局 barrier（等全部任务到达）后一次性 bulk 迁移（经 host-staged 通道，
  禁止 D2D 绕过）+ 单 kernel。旧实现不等到达即传、或用 D2D 隐藏通信成本，均为伪影。
B 动态非批处理：逐段迁移 + 逐段 sync；段门控 = 段内最后任务已到达；单流。
C Ferry：自适应批 + 独立 H2D 汇聚流 + D2H 完成 event 依赖的分向流水 + event 依赖计算；
  批门控 = 批内最后任务已到达；
  在途窗口 pending_ahead。
D1/D2 公平对照（与 C 共用同一执行引擎，唯一差异 = 窃取粒度）：
  D1 = 每次窃取 1 个任务（one-steal，B 的粒度，但保留 C 的异步流水与批执行）；
  D2 = 每次窃取 victim 一半（steal-half，不按消费批截断，StealHalf 语义）。
  用途：把 C/B 总倍数拆为"执行引擎贡献（B→D1）"与"窃取粒度贡献（D1→C）"，
        并回应"为何不偷一半"（D2 vs C）。
门控总则：任何批/段在其最后任务到达前不得提交；出现负延迟即作废重调参。

【6. Workload B 参数（锁定，已实现）】
payload：low/med/high = 4KB/16KB/64KB。到达校准：tick 使 arrival_span ∈ [0.5,2]×
service_span；p50<0 作废。bursty = 64 任务同 tick 集中 + 行间指数静默；skewed = 帕累托。
tasks 64K–256K（总迁移量 64MB–4GB 覆盖饱和区）。
trace（新增，真实性列）：arrival=trace 读 FERRY_TRACE_CSV（默认 data/arxiv_arrivals.csv，
csv 为归一化 arrive_ticks；行数不足直接报错退出，禁止静默改分布）。转换器
tools/trace_to_arrivals.py 用整条 Mooncake trace 的 1180 个聚合桶当到达过程，
桶内 sum(input_length) 加权摊任务到 --tasks，ticks-per-span 对齐 steady 量级（32768）。
两种真实负载：arxiv（桶突发 2.89×）/ toolagent（3.19×），互为对照。

【7. Workload A（已实现已跨卡）】
QSA-style miss 流：多请求持续 decode，每 step 每层选 128–512 个 C4 block；步间 reuse≈66%；
层间独立；host pinned slab 存逻辑 KV，GPU 每(请求,层)固定热缓存（1×/2×/4× 档）；
miss 经批回填。执行器三模式 = kv_exec.cuh（A 步末同步 / B 逐 C4 / C 自适应批+重叠）。
跨卡结果见【0】。数据源是 host pinned slab（与设备无关），热缓存/kernel 驻 dst。

【8. 指标口径（锁定）】
延迟 = 完成时刻 − 到达时刻（event 级）；makespan = 首到达→末完成。
通信量 = 真实迁移字节；迁移段数 = 通信放大代理。
overlap ratio = 1 − T_pipe / (T_comm_alone + T_compute_alone)（R5 实现三项独立计时）。
Workload A 专属：hit rate、miss 字节/token、p50/p99 step。
扩展效率 = N 卡吞吐 / 单卡吞吐（4 卡窗口出）。

【9. 实验矩阵与消融开关】
开关：m1_p1{false,true} × adaptive{false,true} × overlap{seq,pipe}
      × n_in_streams{1,2} × queue{per-thread,wave} × 粒度{C4,固定页,固定1–4MB,自适应}
      其中 n_in_streams 仅表示 D2H 流数量，不作为 M1 消融；
输入：arrival{steady,bursty,skewed/mixed,trace} × hot{1,2,4}× × sparsity{4,16,64}KB × skew{bal,imb}
硬件：1（环回）/ 2（集群 PCIe4，已出）/ 4（vast PCIe3，已出；集群 4 卡待窗口）。
必做消融（R4）：去 M1（m1_p1=true，P1 单流交替、无独立 H2D 分向重叠）；
去 M2（adaptive=false，固定粒度）；去 M3（overlap=seq）；去本地优先（B 语义）。
公平基线（W6，run_multigpu 模式 3/4）：D1=one-steal、D2=steal-half，
与 C **共用同一执行引擎**（同自适应批、同流水、同在途窗口），唯一变量 = 窃取粒度；
用于把 C/B 总倍数拆成"引擎贡献"与"粒度贡献"。
建议：批大小曲线、hot 档位、per-thread vs wave。
不扫：语义模式、反压阈值、NVSHMEM、serving SLO、GNN/MoE 参数。

【10. 工程约束（七条，违反即死锁/假阴性/跨卡崩溃）】
1. 算通重叠只靠 event 依赖，不依赖跨 stream kernel 并发；队列+计算用单 kernel role-partition。
2. 迁移源必须驻留设备侧；host 数组不能作 HostStagedChannel 的 D2H 源
   （Workload A 例外：host pinned slab 本身就是源，通道对其只走 H2D 语义——由 slab_offset
   直供，不经过 D2H 段）。
3. 合成负载禁用随机字节→float（signaling NaN 位模式差异）；校验一律位级 memcmp。
4. 小总量会被自适应合并为单批；端到端 target_batches=8 保证流水窗。
5. CUDA event/stream 必须在 cudaSetDevice(src) 之后创建（跨设备 record 报
   invalid resource handle；单卡环回不暴露，跨卡必现）。
6. HostStagedChannel.submit() 会把上下文切到 src；调用方在 dst 流上启动计算 kernel 前
   必须 cudaSetDevice(dst)。
7. HostStagedChannel 析构会把上下文切到 src 销毁资源（现已恢复调用方设备）；
   任何「构造-使用-析构」块之后启动 kernel 前，仍必须显式 cudaSetDevice(dst)。
8. 通道 ring 深度必须 ≥ 在途窗口 pending_ahead + 2：event 依赖批持有在途批的
   h2d_done event，ring 浅于窗口时 slot 复用（event 被 re-record）发生在出队前，
   会等错批（伪同步）。run_ferry_abl 与 run_overlap_ratio 均按此建通道。

【11. 平台与执行策略】
共享集群：他人进程常驻（vLLM 驻留显存但 util=0% 时可用；util>0 或他人训练时禁用）。
监控线程 watch_gpu_window.sh 常驻（120s 轮询，日志 watch_gpu.log）。
⚠️ **同机邻居争用（2026-09-23 实测发现，影响全文集群数据口径）**：
  当 GPU0/1 被他人 vLLM 占用（util 100%）时，GPU2/3 的重复测量呈**双峰**：
  快模 ≈215–225ms、慢模 ≈250–272ms（差 15–25%），**与自身配置无关**
  （`--sat-mb=4.0` 参数未变，前 5 次全快模、后 2 次全转慢模）。
  机制：若邻居为 TP≥2，其每 token all-reduce 走 PCIe+host 通路，**与本系统
  host-staged 迁移争用同一 PCIe/内存带宽**。
  纪律（据 result/a5_b2_2card_20260923.md §5）：
  ① 集群 2 卡 A/B 比较**必须多重复并用均值**，单次差异 <25% 不可信；
  ② 这解释了集群 std 高而 vast 独占机 std 仅 1–8% —— **vast 干净数字不可被
     集群噪声数据替代**，两平台分工的必要性再获支持；
  ③ 若论文报集群 2 卡主数字，须声明"共享集群 + 同机邻居 PCIe 争用"，
     或择邻居空闲窗口重测（watch_gpu_window.sh 已挂）。
数字层级（v5）：环回=机制证据；集群 PCIe4 2 卡=绝对主数字；vast PCIe3 1–4 卡=扩展效率/
负载均衡/跨平台鲁棒性（集群 4 卡得窗口后再补一组绝对数字）。
**跨平台纪律**：换机器必须先跑 probe 三关（topo 无 NV#、P2P 全 0、bench_comm ratio）
+ 与集群参考对齐；绝对延迟/吞吐不得跨平台拼表，比值（C/A、C/B、M1、E）可跨平台。
租卡流程见「说明文档（大模型运行前必看）.md」（含验收清单、W3 命令、结果回收）。
预期差异：带宽越低 → T_comm 越大 → overlap ratio 越低（公式必然），M3 相对价值略升；
批大小饱和点可能右移，**批大小曲线必须两平台各报一条**。

不写成 QSA/HiSparse 跟跑；不滑回「泛稀疏」或 GNN；不模块堆叠；不抢 Shetty 单卡队列；
不复现 8×256K 容量数字；Portable 相对 B 无稳定收益即停扩。
新增：
- R1 修正后 C 仍 ≤A → 先查通信占比（加 payload/tasks），不得改结论口径（已解除：R3 全正收益）。
- 窗口长期不可得（>2 周）→ 4 卡矩阵降级，主结论挂 2 卡 + 机制层倍数（已由 vast 平台解除）。
- **批窃取净收益偏低（W6 实测 ~1.13×）** → 不得靠它撑主结论；改为"引擎 1.81× + 粒度 1.13× +
  窃取次数 ↓165×"的三段式表述，若 4 卡重复后 C/D1 仍 ≈1.1× 则如实写"粒度收益有限"。
- **跨平台混用** → 已立纪律（见【11】）；任何跨平台表格必须区分绝对量与比值，且注明 PCIe 代数。
- 单次跑无方差 → 已列为必做（见【13】剩余 A），报均值±标准差或范围。

【14. 推荐叙事（冻结）】
「Shetty 等解决了单 GPU 上可线性化、有进度保证的有界并发队列；但 LLM 稀疏注意力的持续
decode 把任务变成 host 完整 KV 与 GPU 热工作集之间的 miss 回填：静态划分与大同步在到达
偏斜、层间 locality 漂移和细粒度 PCIe 往返下放大通信、抬高尾延迟。与 Llumnix 的预拷贝式
请求迁移不同（其所迁 KV 源端已不再需要，传输离临界路径、停机近零且与序列长度无关），
本文所迁数据是消费端**当前步骤即需**的，只能挤在同一条无 P2P 的 host-staged 通道上
与 miss 回填争带宽——这正是本文的难点所在。我们构建不依赖 P2P 的
host-staged 多 GPU 运行时：数据面**采用**既有的分向重叠与算通重叠手段
（独立 H2D 汇聚流 + D2H 完成 event + event 依赖流水；标准做法，引
MAST[ICDCS'25]/CoCoNet/PipeMoE/Tutel），并报告二者在该 regime 下**非加性**
（单独各 ≈1.0×、联合 1.92×，因单流交替下传输流被占满使计算无处重叠）；
本文真正主张的是**该约束下的迁移决策**——何时迁移值得、该迁什么内容。
在请求级稀疏 decode 的多卡 KV 调度上，我们以前缀组为局部性单位（组 = 前缀缓存
单位，请求到达即带归属卡）建模"亲和 vs 均衡"的真实权衡：无局部性时 round-robin
分发支配一切运行时重分配（C/RR 1.17±0.10，含 Llumnix-style 全局重平衡亦不敌
RR——遵守 dest 无收益）；开启前缀共享后迁移的价值显形——遵守亲和的运行时调度
把 refill 砍 41–53%（C 660–733 vs RR 1256.5MB，C/RR 反转 0.73–0.82±，28 次中
27 胜），成本感知的值过滤（E）四格全部最优（E/C 0.90–0.98，迁移再省 30–60%）。
已证（均为多次重复的 mean±std，不用单次值）：2 卡真实跨卡（集群 PCIe4）+ 4 卡（vast PCIe3）
控制面与扩展性。偏斜下静态划分 imb 达 0.80（2 卡）/1.38（4 卡），本设计以 ~100 次批窃取
拉回 0.017–0.050，窃取次数比单任务粒度低约两个数量级；4 卡偏斜档 C/A 1.47–1.60（±0.04–0.14），
C/B 1.72–1.87。**加卡收益几乎全部来自控制面**：强扩展 E(4)=1.395 而静态划分 A 仅 1.04×；
弱扩展 E_weak(4)=1.603（每卡效率 0.401，受单卡 host-staged 带宽约束）。
水位阈值跨 5× 范围仅改变 makespan 3.8%（鲁棒，非需精调的超参）。
跨两平台带宽相差 2× 时机制倍数保持（M1 1.85→1.90×，M1×M3 1.92→1.93×，T_compute 逐位一致、
T_comm 1.84×）→ 绝对数字平台相关、比值平台无关。
措辞纪律：C/B 总倍数=引擎贡献（4 卡 5 次 1.54–1.57×）+粒度贡献（1.12–1.14×，
且 C/D1 随 N 单调升 1.00→1.12），不得笼统归因"批窃取"；范围声明：卡间为分区（DP/PD-replica）而非 TP 切分；
集群 PCIe4 四卡绝对数字待窗口补齐。」

【15. 抽象模型（insight 收束 · 由【0】实测反推，非先验假设）】
15.1 记号与实测标定
  g    批字节 = **本节简化模型的决策变量**；p 单任务 payload（4/16/64KB，medium=16KB）
       WlA 完整动作另含请求集合、源/目的卡、迁移内容；不可与传输 chunk 大小混为一谈。
  B(g) host-staged 有效带宽，饱和型（probe --bw 实测，results/w3/bwscan.txt）：
       vast PCIe3（GB/s）：16KB→1.21 64KB→2.54 128KB→4.04 256KB→4.55
                           512KB→5.14 1MB→5.51 2MB→5.73 4MB→5.85 16MB→5.95
       集群 PCIe4：≥1MB 饱和，16MB→11.9（两平台 g* 同阶，纵轴 ≈2×）
  g*   饱和点 = B(g) 达渐近值 90% 的最小 g ≈ **0.7–1MB ≈ 64 任务 @16KB**
  W    在途窗口 pending_ahead = 4；Q_i 卡 i 队列长度；imb 完成数变异系数
  实测锚点：C 固定策略 mean batch = 254–256 任务 ≈ 4MB（= max_mb，符合预期）

15.2 核心耦合（insight 本体）
  CPU 窃取谱系（Cilk / StealHalf / BWoS）：迁移单位 = **指针**，成本 ≈0
    → 粒度只影响均衡质量，是**单目标**问题，故"偷一半"可以是普适答案。
  请求级 KV 迁移（Llumnix，OSDI'24）：借 VM live migration 的**预拷贝（pre-copy）**思路——
    KV 只追加（append-only），已算完的 KV 不再被修改，故可后台拷往目标实例、源端
    同时继续解码；**拷贝带宽远高于 KV 生成速率 ⇒ 积压可排空**，最终仅 1 次迭代需
    同步交接 ⇒ 其报告近零交接停顿。注意：不可变 KV 仍可被源端后续 decode 读取，
    预拷贝不等于迁移无成本，也不能推出它不与推理争用带宽；需区分交接停顿与总迁移时间。
    本文比较的是 host-staged 共享通道下的具体代价结构，不主张其他系统不面对迁移权衡。
  **host-staged 多 GPU（本文 regime）：迁移单位 = 数据本身，且批粒度落在
  通道饱和曲线的陡峭段上** → 同一个 g 同时决定两件相反的事：
    ① 带宽效率 B(g)：g↑ → 单位字节成本↓（压向大批）
    ② 重分配响应粒度：g↓ → 才能细粒度纠偏、压低尾延迟（压向小批）
  ⇒ **一个决策变量、两个相反目标，且二者被硬件曲线耦合** = 本文问题本体。
    这是上述两个谱系都不面对的 regime，也是 Ferry 唯一可辩护的 novelty 落点。

15.3 代价模型（三项，符号方向由实测定，不是推演）
  makespan(g) ≈ V/(N·B(g))            [T1 传输：g↑ 则↓，g≥g* 后触底]
              + c_s · (V_mv/g)        [T2 重分配开销：窃取次数 ∝ 1/g，g↑ 则↓]
              + α · g                 [T3 纠偏量子/尾延迟：g↑ 则↑]
  V 总迁移字节；V_mv 需重分配的字节；c_s 单次窃取开销；α 失衡敏感度（∝imb、∝N）
  ⚠️ **T2 在当前 Workload B 实现中不是传输成本**：payload 恒从 pool 拉，窃取只搬
     任务 id，B 与 C 迁移字节相同（【0】实测 512.00MB 全等）。故 T2 = 全局锁争用 +
     重新取活延迟，**非带宽**。带 KV 迁移成本的 T2 要靠 Workload A 跨卡（见 C1）。
  T1、T2 递减而 T3 递增，并不足以保证可行区间存在内部最优点。
  在理想饱和区 B(g)=B_inf、α>0 时，驻点为 sqrt(c_s·V_mv/α)，还须裁剪到
  可行区间并与非饱和区候选比较；α=0 时该区内偏向最大可行批。
  因此 g_opt≈g* 仅是条件性经验假设，不是上述模型的必然结论（见【16.5】）。

15.4 模型对已有实测的解释力（逐条对账，含不利数据）
  ① M2 端到端 ≈0.99–1.00× 但段数 1024→267：默认已运行在 4MB ≥ g*，**T1 已触底**
     → 吞吐无差异（符合），收益只体现在 T2（段数/往返）。模型解释了"M2 只主张
     段数不主张吞吐"这个原先只能描述、无法解释的边界。
  ② D2(steal-half) ≈ C（0.996–1.002）：victim/2 与消费批**都 ≥ g***，同在 T1 平台段
     且 T2 同量级 → 必然无差异。**这不是"偷一半没用"，而是"两者都已在饱和区"**，
     回应 StealHalf 的正确方式。
  ③ D1(one-steal) 差 1.12–1.14×：窃取粒度 1 任务 → T2 爆炸（17.5K vs ~100 次，
     ≈175×）。模型预测惩罚来自 T2 而非 T1 —— 与"迁移字节全等"的实测一致。
  ④ 平衡档 C/D1 仅 1.02–1.08：imb≈0 ⇒ α≈0 ⇒ T3≈0，且 V_mv≈0 ⇒ T2≈0
     → 粒度失去作用面。**模型给出"粒度收益条件于偏斜存在"的机制解释**。
  ⑤ C/D1 随 N 单调升 1.000→1.066→1.098→1.122：N↑ 使锁争用（c_s）与失衡（α）同增
     → T2、T3 权重上升 → 粒度决策价值上升。模型预测该曲线单调，实测单调。
  ⑥ 阈值 thr 跨 5× 仅变 3.8%：thr 只改**何时**触发窃取，不改 g → 不进入三项主项
     → 必然不敏感。模型解释了这个"负结果"为何是应然而非侥幸。
  ⑦ B2/E 单卡冒烟仅 +1.7–2.5%（噪声级）：单卡 imb=0.000（实测）⇒ α=0 ⇒ T3=0；
     且可见工作量巨大 ⇒ E 的 eff 被钳到 max_mb ⇒ E≈C（实测 mean batch 242.7 vs
     254.0，几乎同批）。**模型事先预测了这个"无增益"，故该冒烟结果支持模型而非反证。**
  ⑧ B2/E 4 卡 steady/imbalanced（2026-09-27 PCIe4 独占机 sat=1MB 7 次）：
     E 相对 C 仅 **+0.79%**（paired p=0.115 边缘不显著）→
     不利数据（量小于 B1 的 1.12×）。模型解释：N=4 α≈1.38，但 visible≈NT 恒成立，
     eff≈4MB（C 的 219=3.96MB 与 E 的 211=3.82MB 只差 3.5%），
     T1 已同平台段，T2/T3 差量 < 组内 4% std → 噪声级。**不是模型错，是本 regime 已饱和。**
  ⑨ B2/E 4 卡 bursty/imbalanced（2026-09-27 sat=1MB 7 次）：
     E 相对 C **-4.12%**（paired p=0.727，方向反，含 outlier r2=236.72）→
     不利数据，直接打脸 P2。诚实解释：bursty 下 occ/g 波动剧烈，
     E 用 `visible_mb = occ+srco` 的**瞬时**估计在相位错位时会在浅队列时夹
     到过小批（E 批 212 vs C 220，虽然差量仅 3.6%，但 bursty 到达的尾部 1 次
     小批 + 锁争用放大 outlier → E 均值被拖慢 4%）。
     → 改进方向：在 E 决策加"最小批下界钳制 = max(saturation_mb, g*_safe)"，
     避免瞬时浅队列小批长尾。**不利数据⑧⑨必须入对账表，不可藏。**
  ⑩ WlA-E（2026-09-30，4 卡 7 次，C1 的 payload 随窃取迁移 regime，有利数据）：
     E/C = 0.947–1.008（吞吐不可区分），migr −31%~−92%、steals −35%~−80%、
     imb 0.037–0.144 vs C 0.213–0.364、ref=7–10/格（决策遥测活着）。
     **模型解释：WlA 里 T2 是真实带宽项（每次迁移 = 24MB D2D ≈ 4.4ms）；C 的
     水位策略不看 T2 → 过度迁移（实测 2.7× 于平衡所需）；E 的价值过滤
     （剩余工作 ≥ margin×成本）偏好剩余步多的请求 → 每字节承载更多工作 →
     少迁且更均衡。⑧⑨ 的"regime 已饱和"解释在此被证实：同一决策框架换个
     regime 即有增益——不是框架错，是 WlB 无耦合对象。**
     收益结构与 ①④ 同构：不在吞吐（T1 已饱和）而在 T2/T3 开销——"决策收益
     在开销不在吞吐"现为跨 Workload 的一般规律。
  ⑪ kv-mode 轴 v1（2026-09-30，4 卡 4 格×5 次，results/wla_kvmode_20260930.md）
     ⚠️ **本条已被 ⑬ 的 112 跑重跑推翻，仅存档以保留证据链**：
     E/C = full 0.86–1.09 | delta 1.22–1.36 | drop 1.02–1.12，当时解释为
     "E 的价值 = 记账保真度"（full 收益侧无账 → 决策无从发挥；delta/drop
     补上收益侧 → 值过滤显形）。该解释的 delta 分支已证伪（见 ⑬）。
     当时已如实登记的中介效应风险（C(delta) 慢于 C(full) 的逐槽 submit 开销
     可能中介 E 的优势）正是后续查明问题的线索——**风险登记制度有效**。
  ⑬ kv-mode 轴 v2 · delta 批量化重跑（2026-10-04，4 卡 4 格×4 模式×7 次
     = 112 跑，记录 results/wla_kvmode_20261004.md）：
     **一条升级 + 一条作废，两者都必须进论文。**
     (a) 升级：C(delta)=282.0±16.9ms 快于 C(full)=315.3±48.4ms（0.894×）、
         迁移字节仅 45%（250 vs 550MB）⇒ 增量迁移的字节节省在批量化后
         第一次兑现为性能收益（v8 的"delta 慢"= 逐槽 submit 的实现缺陷，
         离线微基准：24MB 逐槽 9.53ms vs 批量化 1.52ms vs full 1.41ms，
         每槽 6.2µs 与数据量无关 ⇒ 是 submit 次数的函数）。
     (b) 作废：E/C = full 0.94±0.11(21/28) | **delta 0.99±0.09(15/28，与
         平手不可区分)** | delta-naive 0.74±0.12(27/28) | drop 0.97±0.10。
         v8 的"delta 轴 E +22~36%"**只在逐槽路径复现**；机理 = naive 下每次
         迁移昂贵，E 少迁 65%（88.3 vs 298.4MB）⇒ 少付的是**实现缺陷税**，
         不是真实迁移成本。批量化抹平该税后 E 的决策优势随之消失。
         ⇒ **"full 平手 → delta +22~36% → drop +2~12%"的单调链作废。**
     (c) E 的正确定位（取代 ⑪ 的"记账保真度"叙事）：**等性能下的迁移经济性**
         ——四档模式 makespan 与 C 平手或小幅优（0.94–0.99），但迁移量始终
         显著更少（delta: −65%）。这与 ⑩ 的 WlA-E（migr −31~−92%、imb 更优、
         吞吐不降）完全一致 ⇒ **E 的收益一贯在开销侧而非吞吐侧，跨 regime
         跨 kv-mode 稳定**。这个口径比"吞吐增益"弱，但经得起批量化检验。
     (d) 反向印证 C2：naive 下 C/RR 退回 1.09±0.18（反转消失），而批量化
         delta 0.75±0.10、full 0.83±0.16、drop 0.80±0.08 ⇒ **局部性收益的
         兑现依赖"迁移必须高效"**，实现缺陷足以吃掉全部结构收益。
     (e) 新增常设 ablation（正面系统发现）：`--kv-mode delta-naive`。论文写法
         "增量 KV 迁移必须批量化：逐条发送（6.2µs/槽的 submit 建链与 ring
         反压）使 24MB 迁移慢 6.8×、系统级慢 1.47×，甚至劣于整段全量复制
         （1.31×）——与 Raft AppendEntries 的批量化教训同构。"把潜在的
         "基线做差"质疑转化为可引用的工程结论。
  ⑫ C2 局部性 regime（2026-10-04，4 卡 4 格×7 次，记录 results/wla_c2_20261004.md）：
     C/RR = 0.73–0.82±（C2 关时 1.17±0.10）；E/C = 0.90–0.98（四格全 <1，
     migr 比 C 少 30–60%）；C/LLX = 0.71–0.81。
     **模型解释：C2 把收益侧的账补全（与 ⑪ 同一主题的最后一块）。** full 模式
     refill 位置无关 ⇒ RR 零成本均匀化支配（基线矩阵，⑫ 的对照组）；前缀共享使
     refill 位置相关 ⇒ 迁移 = 保局部性 + 纠失衡双头收益，RR 付冷启动
     （+517–599MB，×1.61–2.03），LLX 付前缀缓存丢失（refill 全价）。**E 的值
     过滤在高局部性 regime 最优：只迁"值得迁"的请求 = 少付 T2 又保住组局部性
     ——成本×收益联合决策的完整闭环（C1 成本侧 + C2 收益侧）。** 迁移量-性能
     单调性反转：C2 关时迁移越多越慢（RR 0 < LLX 171 < E 514 < C 727MB，
     makespan 同向上升）；C2 开时迁移最多的 C 反超零迁移 RR——迁移从纯成本项
     变成收益项的直接证据（论文可作"何时迁移值得"的一图两框）。
  作用域声明：本模型只刻画**控制面**（g 的选择）。M1/M3（分向重叠、算通重叠）属
  **数据面**，与 g 正交——这解释了为何 M1×M3 协同 1.92–1.93× 在两平台保持、
  且不随 g 策略变化。

15.5 可验证预测与反证条件（B2 四卡 2026-09-27 实测已逐条判读）
  P1 g_opt ≈ g*：`--sat-mb` 扫 0.125/0.25/0.5/1.0/2.0MB，E 最优落在 g* 附近且为内部点。
     **判定（4 卡）**：✅ 最优 sat = **1.0MB（= g*，内部点）**，落在模型预测位形；
     但 5 档 Δ=3.93ms、Welch p≈0.865 **曲线整体平**，P1 仍是弱证据（需更大 N/任务量重扫）。
     ▸ N=2 实测仍保持"曲线平"（2026-09-23 记录），与 4 卡一致，属 regime 效应，非机器。
  P2 E 优于 C 仅在 α>0 且队列浅：4 卡 × imbalanced × bursty 最明显；steady 深队列 E→C。
     **反证保留**：balanced 档 E 未出现显著优于 C（与预测一致，不是反证）。
     **判定（4 卡 sat=1.0）**：✗ 预测的**强侧 bursty 失败**（E 相对 C 增益 **-4.12%**，方向反）；
       弱侧 steady 深队列 E→C **+0.79%**（方向对但 p=0.115 边缘）。
       根因：Workload B 下 E 批决策被 `max_mb=4MB` 上限始终夹死，与 C 批差 <9%，
       T2/T3 差值淹没在 3–6% 的组内 std。
       → 不修改 T3 假设；但将"预测失败 regime 边界"明确限定在 pool-only / payload 不随窃取迁移。
     ▸ N=2 初测（2026-09-23）仍保持"E→C 且无增益"，与 4 卡同方向，属一致。
  P3 增益随 N 上升（与 C/D1 同向单调）。**反证**：若 4 卡 E≈C 而 2 卡 E>C 即矛盾。
     **判定（4 卡）**：✗ N=2 C/E=0.986 → N=4 C/E=1.008，**反单调 2.2%**（仍在噪声内，
     但未观察到单调升），P3 在 2→4 卡段未证实，需 8 卡或 Workload A 重判定。
  P4（v7 新增，WlA regime 的跨平台可证伪预测）：E 的迁移节省在带宽收窄平台应放大
     ——PCIe3（0.50× 带宽）迁移成本×2 → C 的空转代价×2 → E/C 的 migr 节省比例拉大，
     且 T_E/T_C 可能降至 <1（这里明确使用耗时比，C 的空转开始吃吞吐）。
     **判定待 vast 最后一跑**（判据 = E/C 与 migr 节省随带宽的变化方向；
     反证 = PCIe3 上 E/C 差距不变或缩小 → "带宽耦合"主张降级）。
  **诚实结论（v7 修正，覆盖 v6 版）**：B2 的"实时决策吞吐更优"在 Workload B
     （pool-only）确实不成立（v6 结论维持：P1 弱证据、P2/P3 ✗）；但 C1/WlA-E 证实
     这不是决策框架的失败，而是该 regime 无耦合对象（T2 恒定）——同一框架在
     payload 随窃取迁移的 regime 给出 −31%~−92% 迁移 + 更优均衡 + 吞吐不降。
     论文结论收束为八条：① g_opt≈g* 判据（WlB）② WlB 固定批已近似最优（负结果
     + 适用边界）③ WlA 上成本感知迁移决策复活（正结果，机理 = T2 真实化）

【16. 可执行形式化草稿：何时迁移值得，以及如何少迁而不拖慢】
状态：问题定义与受限命题草稿；算法、遥测、反事实回放均待实现。已有 E 不自动继承
下述保证。v9 的“E 四格最优”仅是当批均值描述，当前口径以 v10/15.4⑬ 为准。

16.1 研究问题与边界
  主问题：在亲和性导致的存量失衡下，能否依据接收卡负载、有效缓存和通道争用，
  识别值得执行的迁移动作，并在完成时间预算内减少迁移流量？
  不把“发现批传输/算通重叠”当新颖性；拟检验的贡献是可校准的在线决策及其适用边界。
  full、delta 都付真实搬运成本；drop 把一部分代价转移到后续 refill，不能记为零成本。
  C2 关闭时 RR 在已有矩阵领先，不代表无局部性时迁移永远无益：到达后服务时间变化、
  设备速度变化或已有积压仍会产生迁移收益。C2 开启也不保证迁移必胜。
  不要求“定理+跨节点+指定倍数”才能投稿；这些不是会议的通用硬门槛。

  状态 s_t：
    每卡常驻请求/剩余步估计/服务时间估计、各前缀组的有效块集合和物理槽映射、
    在途传输、通道队列/带宽、可用 staging 容量。真实 serving 不得预知输出长度；
    synthetic 中已知剩余步仅作 oracle 上界，在线策略需用预测并测误差。
  动作 a=(i,j,S,m,g)：源卡 i、目的卡 j、请求集合 S、迁移内容 m、传输 chunk 字节 g。
    m 属于 full/delta/drop；a0=不迁移。请求批大小 |S| 与 chunk g 是独立变量。
    同组共享块按有效身份计数；“缺失块并集”是理想下界，实际传输按实现记账，
    不把尚未实现的去重收益计入算法。相同组号不保证私有后缀可共享。
  可行动作约束：
    请求只在安全步边界交接；数据、槽映射、有效位/所有权一致后才能恢复执行；
    源端仍有共享读者时不得清掉其状态；目的已有同组请求时不得覆盖其私有块；
    staging 容量、设备上下文、事件依赖与 ring>=pending_ahead+2 均需满足。
    初版保持现有串行迁移控制，避免把并发通信优化混入策略变量。

16.2 目标、对照与统一记账
  局部预测对象：从同一 s_t 出发，冻结后续到达，对当前未完成请求运行至完成，
  执行动作 a 后使用相同的固定后续调度策略，记残余 makespan 为 J_t(a)，单位 ms。
  这不是有限墙钟窗口内“只统计已完成请求”，不会通过拖延未完成请求降低目标。
  全程实验另报 flow time、P99/TPOT、SLO goodput；局部 J 的改善不保证这些指标改善。
  预测净收益 Δ_hat(a)=J_hat(a0)-J_hat(a)，必须相对同一状态下“不迁移”计算。
  审计分解：
    Δ_hat = G_balance + G_cache - C_exposed - C_external。
    G_balance：目的端积压/批处理效率计入后的工作转移收益，不是请求总剩余工作；
    G_cache：相对不迁移的缓存服务时间变化，可正可负；
    C_exposed：关键路径上不能被重叠掩盖的交接/传输/打包/散射开销；
    C_external：对源/目的其他请求及共享 host 通道造成的额外延迟。
  该分解须由同一时间线模型定义，各项不得重叠收费；难以分离时直接预测两个 J，
  分解只用于诊断。RR-C refill 差不能直接当作某次迁移的 G_cache，因为准入也不同。
  迁移服务时间标定：
    tau(i,j,m,V,g,q)=端到端实测表，含 pack、D2H、H2D、scatter、元数据和队列 q。
    若 B_eff=V/tau 已按完整双跳标定，使用 V/B_eff，不能再乘 2；
    若按单向链路建模，串行上界才是 V/B_D2H+V/B_H2D，流水需按时间线计算。
  分别报告有效 KV 字节、元数据、D2H/H2D 实际字节、refill、总 host 链路流量与
  staging 显存。E 少迁 65% 不自动等于总流量少 65%，更不自动等于延迟改善。
  工程主目标：相对冻结的 C+batched-delta 基线，在 T_policy/T_C<=1+ε 的预算内
  尽量少迁移；ε 预注册为 0.03，另报 0/0.01/0.05 的 Pareto 曲线。
  这是评测约束，不是在线已知的 oracle。均值“不显著不同”不能证明等价；
  声称不劣须配对耗时比的单侧 95% 置信上界<=1.03，否则记为证据不足。

16.3 命题一：双卡冻结模型的精确盈亏边界（可直接证明，不主张一般性）
  假设：两台等速 GPU；无后续到达；工作量按服务时间线性可加、无连续批交互；
  初始负载 L_i>=L_j，单位 ms。转移工作 x，0<x<=L_i；源端释放 x 且不因搬运停顿；
  目的端增加 x+m，其中 m>=0 是串行暴露的迁移成本；无缓存收益/其他请求外部性。
  不迁移 T0=L_i；迁移后 T1=max(L_i-x,L_j+x+m)。
  因而 Δ=T0-T1=min(x,L_i-L_j-x-m)；
  **严格改善当且仅当 0<x<L_i-L_j-m**（仍受 x<=L_i 和离散候选约束）。
  证明：T1<T0 等价于 max 的两项都小于 L_i，分别得到 x>0 和 x+m<L_i-L_j。
  若 m 固定且 x 连续可分，L_i-L_j>m 时最优 x*=(L_i-L_j-m)/2；
  否则应不迁移。真实 m=m(x,g,q) 时必须搜索，不能套固定 m 的闭式解。
  反例测试：
    (L_i,L_j,x,m)=(100,0,20,5)：T1=80，无局部性也能获益；
    (100,90,20,5)：T1=115，尽管“剩余工作 x>迁移成本 m”仍然变慢；
    (100,70,20,10)：T1=100，边界不迁与迁移平手。
  意义：当前 E 的“剩余步×step_ema>=margin×cost”只是代理门控，不是净收益保证。
  推广到多卡须把未触及卡的最大负载放进 max；别的瓶颈卡可能让本次改善不可见。

16.4 命题二：预测误差下的保守门控（保证仅限当前候选/冻结模型）
  固定候选集 A_t（含 a0）。假设对所有候选统一成立
    |J_hat(a)-J(a)|<=e(a)，且 e(a) 已知。
  定义净收益下界 LCB(a)=J_hat(a0)-J_hat(a)-e(a0)-e(a)。
  仅接受 LCB(a)>h 的动作，h>=0 为预先设定的滞回余量，则 J(a0)-J(a)>h。
  证明：J(a0)>=J_hat(a0)-e(a0)，J(a)<=J_hat(a)+e(a)，相减即可。
  若误差统一为 e，候选最小预测耗时动作 a_hat 还满足
    J(a_hat)<=min_{a∈A_t}J(a)+2e。
  证明：在预测最优性不等式两侧各加一次 e。此为候选集内加性误差界，
  **不是整个在线调度的竞争比，也不是相对全局最优的保证**。
  实测分位数/bootstrap 区间并非确定误差界；使用它们时只能声称校准覆盖率。
  从多个候选中挑最好者会有选择偏差，须校准同一决策候选集的最大误差，或做
  同时覆盖修正；逐动作 95% 区间不能直接变成被选动作/全程 95% 安全保证。

  待实现策略 F（独立于既有 E，不能事后将新模型称为 E 的证明）：
    1. 步边界抓取一致快照；生成有界候选（源/目的、请求批、内容、chunk），含 a0。
    2. 批内联合预测 J_hat、e、实际搬运字节；不能逐请求独立相加共享缓存收益。
    3. 无候选 LCB>h 就不迁；否则在通过门控者中找最小 J_hat，耗时预测落在
       预注册容差 δ 内时优先较少字节，仍须满足同一个安全门控。
    4. 执行前重新检查版本/所有权；状态变了则重算或放弃，不能复用过期保证。
    5. 完成数据交接再发布状态；记录预测、实际成本、原因与控制面耗时。
  冷却期只作防抖参数，需计入丢失的机会；不宣称杜绝未来所有乒乓。

16.5 粒度命题与暂不承诺的理论
  对 15.3 在饱和区的简化目标 F(g)=常数+c_s·V_mv/g+αg，
  若 α>0、c_s·V_mv>0，则 F'(g)=-c_s·V_mv/g²+α，F''(g)>0；
  饱和区内最优为 clip(sqrt(c_s·V_mv/α),g*,g_max)。
  全域最优还须比较 g<g* 的候选。因此 g* 是带宽阈值，不是普适最优批量定理。
  在线迁移里 V_mv 也随决策变化；固定 V_mv 的推导不能冒充联合策略最优性。
  不预定“常数或 O(log N) 竞争比”：未来到达、服务长度、共享缓存和动态带宽的
  信息模型尚未限定。先完成上述局部证明与有限实例 oracle，再判断是否值得
  研究有界服务时间/固定迁移代价等受限在线模型。不能把静态缓存问题的界直接移植。
  两个命题是基础分析工具，单独不构成论文新颖性；价值待端到端验证。

18.1 四条贡献（**v18 按 A1 实测证据重写；v16 原措辞见 18.1' 作废段**）
  ① **问题适配**：把经典 work stealing（Cilk / StealHalf 谱系：迁移单位 = 指针，成本≈0）
     适配到**迁移成本非零、且与其所省计算量同量级**的 regime——窃取不再只改均衡，
     还要付真实字节（24MB 热集 ≈ 4.4ms D2D，与一个 decode step 同量级）。
     共享 host-staged 通道是该成本的来源之一，**实测代价税 ≈12%**（在位达成带宽
     14.6 vs 离线微基准 16.6 GB/s，results/wla_a1obs_20261015.md）。
     ⚠️ **不得写"迁移挤占关键路径回填带宽是本文难点"**：A1 实测决策时刻并发回填
     P(t) 仅 0.4–1.1MB（max 3.5），而单次迁移 20–150MB ⇒ 二者在决策瞬间几乎不
     相遇，争用表现为**带宽均值的持久下移**而非相位冲突（见 ③ 的 L2 负结果）。
  ② **规则 + 敏感性（措辞改向）**：给出 ε-预算成本门控（τ̂ = κ·V/B_ref + c_fix，
     B_ref 物理参照 / κ 策略旋钮，见 18.3 v19 定义），并给出本文真正可辩护的结论
     ——**该 regime 存在"性能平坦高原"**（正式矩阵 results/wla_plateau_20261015.md
     + 边界扫描 results/wla_rcal_precheck_20261015.md）：
     成本估计跨 **36×**（等效带宽 1.0→36.5 GB/s）时 makespan **全程平坦**
     （C/E ∈ [0.92, 1.09]，全在 ±1σ），而 E 的迁移量跨 **~10×** 变化
     （12.6→137MB）⇒ **估计值可自由为"省字节"而调，性能代价在噪声内**；
     取最保守端可把字节节省推到 **−88%**（vs C）。
     ⚠️ **不得主张"我们的阈值最优"**：高原意味着任何阈值给同样 makespan，
     "提出一个阈值"本身没有分量；贡献在**高原的存在性与其 ε-预算含义**
     （接【16】16.2：T_policy/T_C ≤ 1+ε 内尽量少迁，天然成立）。
     ⚠️ **两个边界均未找到**（规模限制：48 请求/16 步）——"过度保守何时失效"
     是 future work，**必须在论文声明**，不得写成"任意保守都最优"。
     ⚠️ **平坦 ≠ 无效果**：E 相对 C 的节省在全部 16 格成立（bw=8.0 时
     46.9 vs 172.7MB = −73%）；高原描述的是 E 对阈值的不敏感，非 E vs C。
  ③ **验证（单指标，口径收紧）**：在等性能预算内报**迁移字节经济性**；
     冻结模型（【16】16.3/16.5）降为**解释工具**，不作"证明"主张。
     ⚠️ **"减少窃取次数"从本条移除**（实测不成立）：WlA 下 E 的 steals ≈ C 且
     跨跑漂移（如 bursty/bal C=10 vs E=11）；↓175× 属 **WlB 的 D1→C 粒度对照**，
     不是 WlA 的 E。18.4 判据的 steals∧migr 双降（AND）据此改为单条件（见 18.4）。
     ⚠️ **"−65%" 是估计值的函数，不是常数**（v19 预检量化）：该数含三层堆叠
     = 过期常数（v19 查明实为 2.65× 高估，非"30%"）+ 去重未入账 + margin=2；

     ⇒ 报告须给"节省 vs 成本估计"的曲线，不得把某一点的 −65% 当常数引用。

18.2 定位：迁移代价轴（取代"无 P2P 系统"身份）
  抽象（**v18 修正**）：**迁移代价与其省下的计算量同量级**；共享 host-staged 通道
  使该代价再上浮约 12%（在位 14.6 vs 离线 16.6 GB/s）。
  ⚠️ v16 原句"且迁移流量与关键路径回填**争用**同一段带宽"降级：A1 实测 P(t)
  （决策时刻并发回填）仅 0.4–1.1MB ⇒ 争用是**均值税**而非相位冲突，不作机制主张。
  无 P2P / host 双跳只是该轴最贵的一端：
    host 双跳（本平台）  代价最高、与回填争同一条 PCIe → 决策价值预期最大
    PCIe P2P            代价中等、目的卡 x16 仍同时收回填与迁移 → 仍争
    NVLink              代价很低、迁移走独立链路 → 决策价值收窄（Llumnix/MELL 的世界）
  可证伪预测（与 P4 同线）：B_mig ↓ ⇒ 规则相对固定策略的迁移节省与 makespan 优势 ↑；
  B_mig → ∞ ⇒ 规则退化为普通均衡策略，与 C/LLX 无差。

18.3 规则（**v19 定形：ε-预算规则，B_ref 物理 / κ 策略**；L2 前瞻项已判负）
  **R-cal（采纳）**：仅当 剩余工作估计 × step_ema > margin × τ̂(V) 才窃取，
     τ̂(V) = **κ·V/B_ref** + c_fix，其中
       - **B_ref = 物理参照带宽**（端到端双跳；本平台 16.6 GB/s，离线微基准）。
         是**单位换算量**，不是测量/校准目标。X2 扫此轴（换平台只换它）。
       - **κ = cost_scale（策略保守度旋钮）**，预注册。旧公式 `2.0×V/11.0` 与之
         等价当 κ=3.0/B_ref=16.6（V/5.53 ≈ 旧 V/5.5）⇒ **默认工作点不变**。
         旧行为逐字复现：`--mig-bw 11.0 --cost-scale 2.0`。
       - c_fix = kMigDeltaFixedMs（离线标定 52–109µs，已在用）。
  ⚠️ **κ 按 ε-预算规则选**（v19 核心）：预检证明 makespan 对成本估计在 **36×**
     范围内平坦（C/E ∈ [0.92,1.09]）⇒ 在 T_rule/T_C ≤ 1+ε（ε=0.03，16.2）的
     候选中选 **最小字节** = 最保守的 κ。**估计值是策略旋钮，不是测量值** ——
     这推翻了 v18"自校准到真值"的动机（自校准 ⇒ 宽松端 ⇒ 字节节省缩小，见 v19 卷首）。
     κ 网格与 h 一并在留出格标定后冻结，不得事后挑选。
  **L1（观测）保留**：B_eff 在位 EMA（[A1-obs] 行）继续作为**跨平台换算参照**
     与"实现是否达到物理带宽"的健康检查，不直接进默认工作点。
  **L2（争用前瞻项）→ 判负，仅存档**：曾拟 cost ×= (1 + κ·P(t))，P(t) = 决策时刻
     其余卡在途回填。A1 实测 P(t) mean 0.4–1.1MB / max 3.5MB（vs 单次迁移
     20–150MB）⇒ 回填批小、窗口短，该项几乎不触发。诚实结论：**该 regime 的
     争用已被 host-staged 单流饱和吸收，表现为 B_eff 的均值下移，常数项足以捕捉**。
     与 B2/WlB"regime 无耦合对象"同一论证手法。
  R-batch（批大小，**降为可选**）：g = clip(sqrt(c_s·V_mv/α), g*, g_max)（16.5）——
     WlB 的 P1 已判定曲线平（Δ=3.93ms, p≈0.865），WlA 未测；不作主线。
  ⚠️ 规则须对**冻结的 C + batched-delta（含 v17 去重）**基线报 T_rule/T_C 单侧 95%
     上界（【16】16.2 口径）。
  ⚠️ **不得再写"R-thr 即现有 E 的门控"**（v16 原文）：E 的 margin=2.0 / mig_bw=11.0
     是跨多轮矩阵被观测调出的 ⇒ 用现有 E 充当"冻结规则"等于把调过的参数当预注册
     （A2）。R-cal 是新定义，须重新标定并冻结。
  ⚠️ **两个待声明项**：(a) 高原左边界未找到（规模限制，future work）；
     (b) 去重入账（E 成本按每请求 live 求和，重复计同组共享槽）**未实现**——
     属已知细化，其影响远小于 κ 的 36× 作用域，暂以 κ 吸收。

18.4 实验 X1：规则是否少搬、不变慢 + 平坦高原（主结果，**v18 改口径**）
  问题（v18）：同一引擎、同一通道下，规则能否在**等性能预算内**把迁移字节降下来；
  并且该 regime 的 makespan 对阈值位置是否确实不敏感（平坦高原）？
  ⚠️ v16 原问题"能否把**窃取次数**与迁移字节降下来" → steals 条件已移除（18.1③）。
  负载：WlA（请求级迁移，真实 KV 热集）为主；WlB（pool-only）仅作"迁移字节恒定时规则
        无对象"的边界对照（已有数据，不重跑）。C2 开（prefix grp4/stp8）为主档，C2 关为对照。
  对照：RR、LLX-style、C（水位批窃取）、D1（逐个）、D2（偷一半）、规则（R-cal）。
        全部共用 batched-delta（含 v17 去重）迁移实现；naive 只作传输消融。
         ✅ **D1/D2 已实现（v18，wla_multigpu mode 6/7 + runner --with-b1）**：
         D1=one-steal(k=1)、D2=steal-half(k=SIZE_MAX)，与 C 同引擎同通道同触发，
         唯一变量 = 粒度（对齐 WlB steal_req 口径）。初步矩阵（results/
         wla_b1_20261015.md，20 跑）：C÷D1=1.085±0.146、C÷D2=1.020±0.090；
         **粒度收益条件于偏斜**（偏斜档 1.15–1.25×，平衡档 0.97×）——WlB W6
         结论在 WlA 复现。
         ⚠️ **粒度分解主指标 = migr/makespan，不用 steals**：WlA 下 steals 只
         降 1.4×（C=8.9→D1=12.5），远非 WlB 的 ↓175×（WlA 窃取单位本就是请求级
         批）；粒度代价体现为迁移字节（D1 148 vs C 105MB，+41%）。18.1③ 移除
         "减少窃取次数"判据据此再获支持。
  矩阵：{2, 4 卡} × {steady, bursty} × {balanced, imbalanced}，每格 7 次，配对 seed。
  指标：makespan（主）、migr_bytes（主）、refill_bytes、imb、p99 step、steals（仅
        报告不作判据）、**dup%（v17 常设）**、**B_eff/P(t)（v18 常设）**、
        **κ 与 B_ref（v19：成本轴两旋钮，回显于头行）**；
        报 mean±std 与配对比值单侧 95% 上界。
        ⚠️ 服务级指标（flow time / P99·TPOT / SLO goodput）为【16】16.2 的承诺项
        但本节未列（B5）——投稿版须补，或在 16.2 显式收窄承诺。
  判据（v19）：① **ε-预算规则**：在 T_rule/T_C 单侧 95% 上界 ≤ 1+ε（ε=0.03）的
        κ 候选中，选 migr_bytes 最小者冻结 → 主张成立；若全部候选不满足预算，
        如实降级为"等性能下少迁"或负结果。
        ② **平坦高原已闭合**（results/wla_plateau_20261015.md + wla_rcal_precheck_
        20261015.md）：成本估计跨 36× 时 makespan 平坦、migr 单调 ⇒ 18.1② 成立。
        ⚠️ **κ 网格与选择规则须在跑标定前写死并 commit**（预注册证据）。
        ⚠️ steals 不入判据（18.1③：WlA 下 E 的 steals ≈ C，v16 的 AND 判据会误判 FAIL）。
  已有可复用：**v17 刷新版 112 跑矩阵（wla_dedup_20261015，竞态修复+去重后）**——
  C/RR 反转、E 等性能 −65%、delta 最快、naive 反转消失全部复现且口径更干净；

  批内冗余，引用须注明）。缺口：**2 卡同口径矩阵**、规则冻结后的重跑。

18.5 实验 X2：迁移代价轴（定位实验，**v18：导师已确认定位，闸门解除，可实现**）
  问题：规则的价值是否随迁移代价单调变化？无 P2P 是否只是轴的一端？
  ▸ **v18 新增：政策级成本轴已零代码预演**（results/wla_a1obs_20261015.md）——
    `--mig-bw` 扫 8/11/14.6/17.9 GB/s（2 格 ×2 次）：E 的 migr 46→87MB 单调升，
    makespan 全程平坦（E/C 0.94–0.99）。两轴分工须写明：
      **政策级**（mig-bw）= 规则对**成本估计错误**的敏感性（不改真实传输）；
      **通道级**（X2 虚拟通道）= 规则对**真实代价变化**的响应（改传输耗时）。
    前者已有数据且是 18.1② 平坦高原的直接证据；后者仍待实现。
  ▸ **v18 正式矩阵**（results/wla_plateau_20261015.md，4 格×4 bw×7 次 = 112 跑）：
    政策级轴正式定案——E migr 46.9→76.1MB（4/4 池化点单调、16/16 格内单调，
    ×1.62 over bw ×2.24），makespan 跨 bw 变化 ≤1.33× 组内 std。该轴已闭合，
    **X2 只需补通道级**（真实耗时变化），且仿真局限不变（不产生真实争用，
    仅作乐观上界）。
  实现（待做）：迁移走可配"虚拟通道"，耗时 = V/B_mig + c_fix；回填保持真实传输。
        开关默认关闭，关闭时与现有路径逐字节一致（回归必验）。
  扫描：B_mig ∈ {6, 12, 25, 50, 300} GB/s（≈ PCIe3 双跳 → PCIe4 → P2P → NVLink 量级），
        真实锚点 = 集群 PCIe4（≈11）与 vast PCIe3（5.95，待补跑）。
  矩阵：4 卡（主）+ 2 卡（抽 2 个 B_mig 点）× steady/imbalanced × C2 开，每点 7 次。
  报告：规则 vs C / RR / LLX 的 makespan 比、迁移字节比随 B_mig 的曲线。
  判据：B_mig 越低、规则优势越大（单调）→ 定位成立；曲线平坦 → 代价轴主张撤回，
        回到"本平台观测"口径。
  ⚠️ 局限必须写明：仿真通道不产生真实链路争用，"P2P 仍与回填争带宽"在仿真中体现不出，
     仿真结果只作乐观上界；真实争用仅由两个真实锚点支撑。

18.6 Related Work 对位补条（v18 三条 + v22 2610.21500 + v27 EdgeFlow；与 18.1 的切割一致）
  - **BanaServe**（He/Xu/…/Ye，Softw. Pract. Exp. 56(4):424–444, 2026；arXiv 2510.13223）：
    PD 分离下层级权重迁移 + attention 级 KV 迁移 + Global KV Cache Store + 逐层重叠传输；
    明确指出 prefix-cache 路由造成负载偏斜，目标是让路由"不受缓存放置约束"。
    切割：其思路是**擦除**局部性约束（KV 处处可得）；本文在迁移昂贵且与回填争通道时
    **保留**亲和，只在净收益为正时偷。不比数字（PD 分离 vs DP 分区，形态不同）。
  - **MELL**（Liu/Hong/Chen/Li/Guo，arXiv 2501.06709，preprint）：多 GPU KV 失衡下的
    请求迁移，在 token 重算与 KV 传输间自适应切换，在线算法最小化 GPU 数并限制迁移次数，
    竞争比 4/3；以"inter-GPU communication 进步"为使能前提，明确不做 host offload。
    切割：目标是装箱（省卡）而非 makespan；KV 驻 GPU、迁移走 GPU 间互联，落在代价轴便宜端。
  - **ServerlessLLM**（OSDI'24）：MELL 将其与 Llumnix 并列为最相关的 KV 迁移工作（两阶段
    活迁移）；仅作对位引用。
  - **llm-d P2P KV cache sharing**（IBM/Red Hat，2026-08-15 工程博客，非同行评审）：
    准入侧 load-aware 放置 **+ 从对端拉 KV**——"local hits first; portable reuse when
    locality breaks"。EPP 比较"持有最多前缀的 peer"与"按负载选中的目的端点"，差额
    超过实测 crossover（minCachedTokenDelta，含 fabric 争用余量）才拉；传输经 NIXL
    走 **CPU→CPU RDMA**，两端 GPU 都不参与。GLM-5.2-FP8 32×H200：successful
    throughput +4.6~11.1%，三次重复均值 +9.6%。
    切割（**加强本文定位，不削弱**）：① 其决策仍发生在**准入时刻**——改的是新请求
    去向 + 为其拉前缀，**不动热卡上已排队/在跑的存量**；② 数据路径**不碰 decode
    临界路径**（CPU-CPU RDMA，旁路 GPU），而本文迁移是对端**当前步即需**且与回填
    同走 host-staged；③ 其 crossover 对标的是"拉 vs **重算**"，本文对标"迁 vs
    **留在原卡继续排队**"。⇒ 本文 ② 的阈值主张必须声明与之不同的对标对象。
    ⚠️ 不比数字（32×H200 生产栈 vs 4×3090 无 P2P，不可比）。
  - **arXiv 2610.21500**（Ibrahim, Multiverse Computing, 2026-10-15，**单作者 preprint，
    "Each condition was run once"**）：*When the KV Cache Is Slower Than the GPU*。
    PD 分离 + PCP8 的 **prefill** 阶段，LMCache + Valkey 远程 KV 层，GLM-5.3 FP8 / 8×B300。
    远端命中 0.88s vs 重算 0.31s；同步加载使 hit-heavy 流成为不稳定队列（p99 83s、
    GPU 7% 忙）。两项成本模型 T_load = T0 + ns/B，B* = sR = 2.53 GB/s，T0≈0.33s ⇒
    <17k token 的命中在任何带宽下都不如重算；按 rank 分片 + 分区远程层 + 异步加载后
    p99 83.32→0.67s。
    切割：① 阶段 prefill vs 本文 decode；② 决策在**准入时**（加载 vs 重算）vs 本文
    **存量**（迁 vs 留在原卡排队）；③ 数据路径为网络远端存储（1.7–10.8 GB/s）vs 本文
    host-staged PCIe（12–14 GB/s）；④ 被替代方案是重算（GPU 很快）vs 本文排队/回填。
    ⇒ **不撞车，但拿走了成本模型形状**（见 18.1 v22 追加）。
    **可借用的核心洞见**：判断数据移动是否值得，须对照**替代方案的速率**（其原句
    "judge a cache tier against the prefill rate"），而非对照链路延迟 —— 正是 18.9
    盈亏分析的骨架。引用时标注 preprint 与单次运行。
  - **EdgeFlow**（Zhang/Cao/Wu/Chen/Wang，**ICDCS 2026**，arXiv 2610.22172；全文已读）：
    CEC 地理分布式边缘、按层 shard 的分布式推理；节点过载/退出时迁 KV。
    "直接传 KV"与"传 activation 再重算 KV"混合 + 多节点目标选择 + 2-approx，
    最小化迁移时间；真实 PolyLink（100+ 消费级 GPU）+ 大规模仿真，
    900 Mbps 下 vs DKV/ACT/EdgeFlow-G 降 35–39% / 20–29% / 25–26%。
    切割：① 场景 CEC/多节点 shard vs 本文单节点 4×3090 + DP
    请求分区；② 触发 failover/过载 vs 前缀偏斜 + 持续 decode；③ 网络 100–900 Mbps
    vs host-staged PCIe 双跳（12–14 GB/s）且与回填共用；④ 搬 KV shard（+activation）
    vs 搬请求 + 真实 KV 热集（24MB/请求，per-group 去重）；⑤ 成本对象 = 一次性
    迁移时间 vs 本文"迁移 + 迁移后 refill 外部性"（v23–v26：非局部、路径依赖）；
    ⑥ 决策 = 目标节点 + 层分割点 vs 逐决策"迁 vs 留在原卡排队"（n* 盈亏刻画）。
    ⇒ 标题级撞车风险最高，必须显式引用；详见【20】。
  对位总表（同一"KV 该放哪 / 是否搬"问题簇的**六**种解法）：
    避免迁移（准入侧路由：llm-d / Dynamo / AWS）｜擦除约束（BanaServe）｜
    **准入时拉 KV（llm-d P2P）**｜预算内搬存量（Llumnix / MELL）｜
    **地理分布式边缘的 KV 分片迁移（EdgeFlow, ICDCS'26；见【20】）**｜
    **保留亲和 + 代价感知窃取存量（本文）**。

18.9 收束（v22，2026-10-17）：门控在本 regime 最好情况仅无害 → 主线转向盈亏刻画
  触发：v21 κ*(steps) 矩阵（wla_kstar_20261016）+ arXiv 2610.21500 的盈亏框架。
18.9.1 盈亏算术（参数取自代码与日志；本节数字为推算，非新实测）
  - 迁移单位 V = L × hot × c4 = 12 × 128 × 16KB = **24MB**（与 steps 无关，
    wla_slot_off 按 hot_blocks 取模）；@13 GB/s ≈ **2ms < 1 个 decode step**（12–60ms）。
  - 门槛 = margin × τ̂ = 2 × κ·V/B_ref：κ=3 ≈ **9ms**（只拒剩余 <1 步的请求 ⇒ E≈C）；
    κ=48 ≈ **280ms** > steps=16 时单请求全部工作（<200ms）⇒ **全拒**——与实测
    E_migr=0.0 吻合，模型能解释数据。
  - 窃取价值 ∝ 剩余工作 ∝ steps；成本 ∝ V 不随 steps ⇒ 规模越大越"明显该偷"。
  ⇒ **steps=16 的"安全"不是门控做对了，而是小规模下窃取本身不重要。**
     v21 的"安全域随规模收缩"真实含义 = **本 regime 最优策略就是 C（失衡就偷），
     门控最好情况只是无害**。完整 KV 本就驻 host，替代方案（回填/排队）不慢、
     热集小、通道快 ⇒ 需要拒绝的情形几乎不存在（2610.21500 的"对照替代方案速率"）。
18.9.2 门控何时才有意义（推算，待 X2 验证）
  条件：V/B 与剩余工作同量级，即 n* = (T0 + V/B) / t_step ≳ 剩余步数。
    稀疏注意力（热集 = top-k，百 MB 级）：V/B ≈ 1 步 ⇒ 门控无事可做（本文 regime）
    稠密 KV 长上下文（如 8B / 32k ≈ 4GB ≈ 0.3s ≈ 10 步）：真实输出数百步 ⇒ 仍几乎总该迁
    仅在 **快结束的请求 / 慢链路（跨节点 TCP ~1 GB/s）/ 超长上下文** 时门控有对象
    —— 恰是 2610.21500 的场景（网络层 + prefill），非本文。
18.9.3 作废 / 降级（覆盖 18.1–18.4 对应条目）
  - 18.1② "ε-预算成本门控 + 平坦高原"作为**主贡献** → 降级为**负结果/边界刻画**
    （门控在本 regime 不改善 makespan，过度保守在规模 ≥32 步时显著有害）。
  - 18.1③ "−65% 迁移节省" → 仅限"迁移通道字节、小规模/宽松 κ"；总字节口径
    在大规模为负（−15%，v21）。
  - 18.3 R-cal 冻结 + 18.4 判据①（ε=0.03）→ 暂停（判据① 在 n=7 下不可检验，v21）。
  - 18.8 ①'–② "冻结规则→2 卡复跑规则" → 暂停，待 18.9.4 选定主线后重排。
  - 保留不变：delta 批量化、去重、竞态修复、C/RR 反转、归因纪律、B_eff 税 12–26%、
    κ→refill 耦合机制、imb 非充分代理（v21④）——均为与门控无关的独立结论。
18.9.4 后续方向（按优先级；须导师确认后定稿）
  ① **[主线候选] 盈亏刻画（characterization）**：把 2610.21500 的盈亏模型移植到
     decode 存量迁移：n* = (T0 + V/B) / t_step，用已有数据 + X2 虚拟通道带宽轴实测
     n* ≥ 1 步的条件边界。结论形态："稀疏分层 KV decode 中，迁移成本门控在
     B > X GB/s（或 V/t_step < Y）时无意义"——可证伪规律，与 2610.21500 互补
     （prefill/准入 vs decode/存量）。a0/a 同快照成对回放 + per-decision LCB +
     误接受/误拒绝率 + oracle gap **作为测量工具**（逐决策验证 n* 的预测），
     而非作为"规则优越"的证据。
     所需：X2 虚拟通道实现（18.5，已规划）+ 低带宽端点（≤2 GB/s）+ 逐决策日志。
  ② **[配套场景] 多租户外部性**：字节节省的后果落在共享 PCIe 的邻居（【11】已记
     邻居 vLLM 双峰 15–25%）——与门控是否改变自身 makespan 无关，可给 ① 中
     "迁移通道字节"一个有后果的落点。vLLM 只跑不改。
  ③ **[探针，一晚卡时] "选谁偷"而非"偷不偷"**：v21 机制显示 E 的损失来自拒大 V、
     放小 V（偷错对象）。按剩余工作排序选 victim 请求（不做成本过滤）可能在本
     regime 有真实差别。**仅为假设**，须改代码 + 探针验证后再决定是否升级。
  ⚠️ 统计口径（适用于以上全部）：判据须用 ε=0.05–0.10 或同 seed 配对设计
     （v21③）；迁移字节类主张必带批次与 n（v21 跨批次 C_migr 差 24%）。

  - 离线：`wla_counterfact`（src/tools/wla_counterfact.cpp）。复用 missstream.cuh
    的同一生成器与 wla_apply_prefix_sharing（C++，逐位一致）⇒ 字节反事实**零噪声**。
    枚举 a0 / 每候选请求 × {carry, drop}，按 tick 同步推进、逐层逐块调用与 kv_touch
    同语义的 LRU。`--horizon N` 控制视野。
  - 关闭路径：全部快照代码由 `if (snap_on_)` 保护；未设 env 不产生文件（实测 0 个），
    同配置 3 次 refill 644.3/647.1/649.3MB（±0.4%）。
    ⚠️ 执行线程非确定 ⇒ 无法做"逐字节输出一致"的强验证，以代码路径隔离替代。
19.2 阶段1 结论（results/wla_cf_20261018.md；探针：单 seed、单格、48req/16step）
  - **① carry 恒优于 drop（581 配对，0 次翻盘）**：drop−carry = +8.9~10.7MB
    （κ=3: 167 配对；κ=48: 414 配对）。机制 = 迁移与回填同走一条 host-staged 通道，
    drop 省的传输以更多冷启动回填偿还。⇒ **交接模式选择不构成决策维度/贡献。**
  - **② 单次预热惩罚小（中位 0.18–0.51× V，均值 0.68–0.72×，长尾 2.5×）**：
    上一轮所说的"7×"来自整跑 Δrefill（+1159MB vs 省 170MB），是**累计效应**。
    ⇒ **撤回"预热感知成本模型 E-warm 可拉回 Oracle"**（不足以翻转任何决策）。
  - **③ 但成本是路径依赖的**：同批 414 候选，视野 1→2→4→8→全程的 Δrefill 均值
    = +0.31→+0.85→+1.85→+3.25→**+3.62MB（11.7×）**。⇒ 冻结状态下的单步贪心
    成本模型系统性低估约一个数量级。
  - **④ 字节口径下任何单次迁移都是净亏**（Δrefill+transfer ≈ +21MB）⇒ 字节最优
    oracle 必然偏向不迁移，**字节口径无法判定 E 的对错**；oracle gap
    （+3.3~5.9MB/决策，总 118–125MB）**不是误判率**。判定必须有时间模型。
  - ⑤ 旁证：E 的 value 项与真实字节差 **Spearman 0.74** ⇒"收益项算错"不成立。
19.3 保留可写的主张（阶段1 后）
  - **成本路径依赖 / 单步模型低估一个量级**：对 Llumnix / MELL / 2610.21500
    的"单次线上字节"成本框架构成方法论反例（三者均按单次成本记账）。
  - **有界驻留下 drop 交接永远错误**（581:0），可作工程结论。
  - **字节最优 ≠ 系统最优**：若论文用字节节省作主指标，须显式声明；否则与
    时间口径结论矛盾。
19.4 限制（阶段1）
   - 冻结假设：从快照推进到完成，无新迁移/新到达；未模拟其他卡的后续窃取。
   - 单 seed、单格（steady/imbalanced）、单一 hot/sel 点；trace 为合成 QSA 流。
   - transfer 字节按 delta 语义（live 槽 × c4），不含 per-chunk 固定开销。
   - **时间维度完全未建模**——阶段2 的内容。
19.5 阶段2：时间模型与时间口径结论（v24）
  - 模型：`tick_ms ≈ a·resident + b·refill_MB + c`，逐卡拟合（池化会被卡间异构带偏）。
    实测 82 tick / 4 卡：逐卡 R² 0.63–0.86、RMSE 1.1–3.0ms；池化 R² 0.572。
    ⚠️ 尾部时间差 4–9ms ≈ RMSE ⇒ 尾部 12 个决策点只作方向性。
  - **E 总体有效、单次五五开**：12 次接受的批量动作累计 −53.3ms，但仅 6/12 为正，
    最差 +55.5ms（批量压垮目的卡）。⇒ per-request 门控缺"批量容量复核"。
  - **价值函数错位**：`Spearman(E value, −d_makespan)=0.49`；E 用被迁请求剩余工作，
    真实收益是 victim 尾部缩短。
  - **误拒绝集中尾部**（剩余工作小 ⇒ 被拒，但迁走 victim 剩余最多者可平衡两卡）。
  - Oracle gap（本地时间）mean +4.0ms / median +6.2ms / max +55.5ms；误接受 6 /
    误拒绝 12。⚠️ 局部 oracle（仅 v/g），不含另两卡与后续到达。
  - **能写 / 不能写**：
    能写——"成本门控的价值函数应为 victim 尾部缩短，且批量决策需容量复核"
    （有 0.49 相关与 +55.5ms 反例支撑）。
    不能写——"E-warm 显著优于 E"（阶段1 已否证单次预热项；gap 在模型误差边缘）。
19.6 阶段3：路径依赖的稳健性（v25，20 个 (配置,seed) 样本）
  - 采样轴：`--seed` ∈ {42,7,123,2026} × 配置 {base, hot256, bal, req96, steps32, grp1}。
  - **放大倍数**：4 个同号配置 × 4 seed = 16/16，**7.3–14.6×（中位 10.5×）**，
    h1<h2<h4<h8 单调；跨规模/热集/偏斜/并发均复现。
  - **精确零对照**：grp1（无跨请求缓存共享）4 seed × 5 视野**全为 0.0000**。
    ⇒ 预热成本是**缓存共享结构**的属性，非迁移本身；解释 v20 "7×"只在前缀档出现。
  - **符号反转**：steps=32 全程 Δ 4/4 seed 为负（−7.4~−23.5MB，净省字节），
    h1 在 0 附近（2 正 2 负）⇒ 短视野与全程结论可相反。
  - **因此可写的主张**：迁移成本不是决策点可局部测得的加性量，取决于
    (i) 视野、(ii) 缓存共享结构、(iii) 规模；对既有"本次字节/带宽 + 固定开销"
    的成本形式构成结构性反例（非标定误差）。
  - 这是当前**最强、最可辩护**的一条，也是论文主线候选。
  - 仍缺：真实 trace（换合成 QSA 流）、跨平台（vast PCIe3）、2 卡主平台。

【20. EdgeFlow 对位（v27 新增；ICDCS 2026，arXiv 2610.22172）】
20.1 出处与一句话
  - Mingjin Zhang, Jiannong Cao, Tao Wu, Xiangchun Chen, Ne Wang（PolyU / NUDT / WHU），
    "Efficient KV Cache Migration for Geo-Distributed LLM Inference in Collaborative
    Edge Computing"，ICDCS 2026；arXiv 2610.22172（2026-10-15）。本轮已读全文。
  - 一句话：地理分布式协同边缘（CEC）中，LLM 按层切成 shard 放在异构边缘节点；
    节点过载/退出时，把该 shard 的 KV cache 迁到其他节点。它把"直接传 KV"与
    "传 activation 再重算 KV"混合，并选目标节点，目标是最小化迁移时间。
20.2 成本模型（论文 II-B；与我们最相关的部分）
  - 直接传 KV（逐层）：T_kv = 2·L_seq·H_j·B / B_{k,n}
  - activation 传输 + 目标节点重算：
      T_ACT^comm = L_seq·H_j·B / B_{k,n}（= T_kv 的 50%）
      T_ACT^comp = 2·L_seq·H_j²·B / FLOPS_n
  - 混合流水：T_{k,n} = max(T_ACT^comp + T_KV, T_ACT^comm)
    多节点整体：T_MGR = max_{k,n} T_{k,n}
  - 观察：activation 传输量是 KV 的 50%，但重算受目标节点算力约束；两者可重叠，
    因此存在"前 p 层用 activation、其余层直接传 KV"的最优分割点。
  - 关键假设（切割的根）：成本是**一次性迁移动作**的通信时间 + 重算时间；
    不含迁移后消费侧 refill/冷启动、不含缓存共享被切断的外部性、也不含迁移与
    decode 回填争用同一通道的代价。
20.3 机制与算法
  - 三步骤：采集网络/GPU/显存统计 → scheduler 选目标节点 + 分割点 → 混合迁移。
  - Theorem 1：固定 act-layers/KV-layers 后，最优流水是先传 activation。
  - Theorem 2：选哪些层做 activation 等价于选"前 p 层"（只需决定分割点 p）。
  - MN-KVM：X_{k,n}（源 k 是否迁到目标 n）+ P_k（分割层）；每个源只迁一个目标，
    目标显存需放下 shard+KV；目标 min T_MGR。P3 是并行机调度变体 ⇒ NP-hard；
    用 LP 松弛 extreme point + 二分图完美匹配，得 **2-approximation**（Theorem 3）。
  - Algorithm 1 遍历 P_k（O(N·L_k)）；Algorithm 2 做 2-relaxed decision + 二分搜索。
20.4 实验（V）
  - 平台：PolyLink（平台侧 100+ 消费级 GPU；实验用 RTX2080Ti/3060/3090/4090/A6000 Ada
    五类异构卡，NetBird 组网）；后端 llama-box（llama.cpp），不用 vLLM
    （论文理由：vLLM 不支持资源自适应切分）。
  - 模型：Qwen2.5-32B（64 层，H=5120）、Llama3.1-70B（80 层，H=8192），fp16，
    WikiText-2；batch=32，默认 token length=32；初始 6 节点（Qwen）/10 节点（Llama），
    需迁移节点比例 Llama 30% / Qwen 50%；带宽 100–900 Mbps（30% 方差）。
  - 基线：DKV（全量直传 KV）、ACT（全层 activation 重算）、EdgeFlow-G（混合+贪心选目标）、
    BF（暴力最优上界）。指标：迁移时间（s）。
  - 主要数字：900 Mbps 下 vs DKV/ACT/EdgeFlow-G：Qwen 39%/20%/25.1%，
    Llama 35%/29.2%/26%；token=512 时 Llama 40%/18%/26.4%；异构源 41.9–48.2% vs DKV；
    异构目标 41.1–45.8% vs DKV；大规模仿真 40/50 目标时 BF 仅好 15.6%/15.1%，
    但 BF 开销 54 min/325 min vs EdgeFlow 2.37 s/3.22 s。
  - 边界行为：100 Mbps 时 EdgeFlow 趋向 ACT（论文原话）；高带宽端直传占比上升，
    但论文未称完全退化为 DKV。
20.5 与 Ferry 的切割（Related Work 用；六条）
  ① 场景：CEC 地理分布式 / 多节点模型 shard vs 本文单节点多 GPU（4×3090）+ DP 请求分区；
  ② 触发：节点过载/退出（failover）vs 本文前缀亲和造成的 dest 偏斜 + 持续 decode；
  ③ 路径：边缘网络 100–900 Mbps vs 本文无 P2P 的 host-staged PCIe 双跳（12–14 GB/s），
     且与 miss 回填共用同一通道；
  ④ 搬什么：KV shard（整段）+ 可选 activation vs 本文请求 + 真实 KV 热集
     （24MB/请求，per-group 去重、只搬 live 槽）；
  ⑤ 成本对象：一次性迁移时间（通信+重算）vs 本文"迁移动作 + 迁移后消费侧 refill
     外部性"；v23–v26 已实测后者路径依赖、非局部可加（视野 ~10×、无共享则恒零、
     规模足够大符号反转），EdgeFlow 的 T_kv/T_ACT 不覆盖这一项；
  ⑥ 决策粒度：多节点目标 + 层分割点（优化）vs 本文逐决策"迁 vs 留在原卡排队"
     （成本×收益 / n* 盈亏刻画）。
  ⇒ 不撞车；但标题级撞车风险最高，必须显式引用与对位。
20.6 可借用 / 不可借用
  - 可借用（写作）：
    · II-B 的"先算清 direct vs recompute 两条路径的代价，再设计混合策略"结构，
      可直接对应本文"迁移 vs 留在原卡/回填"两条路径 ⇒ 建议在论文加 Cost Analytics 小节；
    · 真实平台 + 大规模仿真的双轨评测（V-A/V-C），对应本文 4×3090 真实锚点 +
      X2 虚拟通道仿真；
    · 基线命名/对照逻辑（DKV/ACT/BF）清晰，可作本文 baseline 表的写法参考。
  - 不可借用（主张）：
    · 不能把 T_kv = 2LHB/B 或 2-approx 作为本文贡献：前者是一次性迁移时间，后者是
      多节点目标选择；本文对象是 decode 存量迁移的逐决策成本，且 v23–v26 已证明
      成本含非局部 refill 外部性；
    · 不能与 EdgeFlow 比数字：Mbps 边缘网络 vs PCIe；模型 shard vs DP 请求；
      迁移时间 vs makespan/字节/尾延迟，形态不可比；
    · 不能把"activation 重算"当作本文的"搬什么"：本文的 delta/dedup/full 是内容选择，
      不是同一层的 activation 重算；两者可在 Related Work 并列，但不能合并。
