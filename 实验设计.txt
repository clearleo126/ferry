实验设计（收束版 v3 · 2026-09-17 · 取代 v1/v2；两版旧稿作废）
场景钉死：LLM 稀疏注意力持续 decode 的 host-staged 热 KV 工作集（QSA-style miss 流）。
v3 = v2 的场景与口径 + R1/R2/R3 实测结果回填 + 删除过期信息（WSL 证据、旧吞吐数字、平台现状过期描述）。

【0. 一页状态（全部为集群 4×3090 实测；环回=机制证据，跨卡=论文数字）】
通道特性（probe --bw，GPU0↔GPU1 与 GPU2↔GPU3 一致）：
- 无 P2P；host-staged 单流 ≈11–12 GB/s，≥1MB 饱和（16MB 时 11.9）
- 单流下「多段提交统一 sync」相对逐段 sync 在 ≥0.5MB 时 ≈1.0×；增益只存在于 <0.5MB
- 双流流水（2×D2H + 1×H2D）：20.36 GB/s = 1.82× 单流
机制倍数（GPU2 环回）：
- H1 批+流水 vs 逐段 sync：fixed-2MB 1.78×；段数 32→21
- H3 算通重叠：1.87×（7.76→4.14ms，计算通信量级相当时）
- 本地队列：4M 任务恰好一次 PASS；wave-batched ≈ per-thread → 降级为消融，不做主张
跨卡结果（R3，GPU0↔GPU1 真实跨卡，vLLM 驻留显存但 util=0%）：
- Workload B（65536 任务；medium=1GB / high=4GB）：
  medium：steady C/A 1.67× C/B 1.97×；bursty C/A 1.47× C/B 2.22×；skewed C/A 2.23× C/B 1.93×；
          段数 1024→267（0.26）
  high：  steady C/A 1.25× C/B 1.45×；bursty C/A 1.09× C/B 1.42×；skewed C/A 1.33× C/B 1.44×；
          段数 1024→1024（大总量下自适应批贴近上限，段数比无优势）
- Workload A miss 流（4 req × 12 层 × 4 steps，57.66MB miss 回填）：
  steady：C/A 5.86×  C/B 1.76×  refill 3690→1227（0.333） p99 11.67→3.87ms
  bursty：C/A 7.99×  C/B 2.29×  p99 16.65→4.82ms
  mixed： C/A 9.40×  C/B 2.74×  p99 16.80→3.63ms
两条科学结论：
① H4 成立：A 的步末同步在突发/偏斜到达下灾难性劣化，C 优势放大至 8–9.4×——「只报平均
   吞吐会掩盖问题」有直接证据。
② M2（批粒度自适应）收益边界清晰：中小总量时段数砍至 0.26；大总量下批已贴近饱和上限，
   段数比=1.0，收益让渡给 M1（流水）。支撑「M1 报吞吐倍数、M2 报段数/尾延迟」的归因分工。
跨卡 vs 环回：C/B 从环回 1.44–2.08× 升至跨卡 1.76–2.74×——真实 PCIe 往返下批处理+重叠
收益更显著（通信越贵，控制面越值钱）。

【1. 一句话主张（冻结）】
面向 LLM 稀疏注意力持续 decode 的 host-staged 多 GPU 运行时：完整 KV 历史驻 pinned host，
GPU 只驻留每请求每层热工作集；miss 经 PCIe 以流水化批传输回填。系统以本地优先队列、
批处理跨 GPU 重分配、计算通信重叠为多卡控制面，在 4×3090（无 P2P、~12 GB/s）上
提升吞吐、降低通信放大、压低突发/偏斜尾延迟。

【2. 机制归因（v2 校订，维持）】
三个机制与消融开关一一对应：
  M1 流水化批传输：dual-stream host-staged channel（开关 n_in_streams∈{1,2}）→ 报吞吐倍数
  M2 带宽感知批粒度：自适应批大小削减段数（开关 MoveStrategy/固定粒度）→ 报段数+尾延迟
  M3 计算-通信重叠：event 依赖的 compute/copy 流水（开关 seq/pipe）→ 报重叠倍数与 overlap ratio
批粒度不与流水混为一谈（v1 的「batched 2.0×」实为 M1 的功劳，probe --bw 已证）。

【3. 边界 / Shetty / 投稿】
不做：GNN、SpMM kernel、MoE EP、PD 分离、NVSHMEM、SGLang/HiSparse 移植、8×256K 整模、
单卡 wait-free 定理。QSA/HiSparse 只是 workload 来源。
两个 P0：单卡原语→多卡控制面；持续 decode miss 流的尾延迟/偏斜评测空白。
投稿：ICDCS 主投；ICS 备选（persistent kernel/profiling）；ICML 不做默认。

【4. RQ】
RQ1 静态划分+大同步在到达偏斜/层间漂移/热缓存失配下是否劣化利用率与尾延迟？（R3 已证：是）
RQ2 本地优先+流水化批重分配能否提升吞吐/扩展效率并降低通信放大？（R3 已证：2 卡全矩阵正收益）
RQ3 仅 host-staged 是否足以成立？批粒度自适应相对固定粒度是否必要？（前者已证；后者 R4 出）
RQ4（增强）强顺序 vs 放松顺序权衡。

【5. 基线语义（锁定）】
A 静态+bulk-sync：全局 barrier（等全部任务到达）后一次性 bulk 迁移（经 host-staged 通道，
  禁止 D2D 绕过）+ 单 kernel。旧实现不等到达即传、或用 D2D 隐藏通信成本，均为伪影。
B 动态非批处理：逐段迁移 + 逐段 sync；段门控 = 段内最后任务已到达；单流。
C Ferry：自适应批 + 双流流水 + event 依赖计算；批门控 = 批内最后任务已到达；
  在途窗口 pending_ahead。
门控总则：任何批/段在其最后任务到达前不得提交；出现负延迟即作废重调参。

【6. Workload B 参数（锁定，已实现）】
payload：low/med/high = 4KB/16KB/64KB。到达校准：tick 使 arrival_span ∈ [0.5,2]×
service_span；p50<0 作废。bursty = 64 任务同 tick 集中 + 行间指数静默；skewed = 帕累托。
tasks 64K–256K（总迁移量 64MB–4GB 覆盖饱和区）。

【7. Workload A（已实现已跨卡）】
QSA-style miss 流：多请求持续 decode，每 step 每层选 128–512 个 C4 block；步间 reuse≈66%；
层间独立；host pinned slab 存逻辑 KV，GPU 每(请求,层)固定热缓存（1×/2×/4× 档）；
miss 经批回填。执行器三模式 = kv_exec.cuh（A 步末同步 / B 逐 C4 / C 自适应批+重叠）。
跨卡结果见【0】。数据源是 host pinned slab（与设备无关），热缓存/kernel 驻 dst。

【8. 指标口径（锁定）】
延迟 = 完成时刻 − 到达时刻（event 级）；makespan = 首到达→末完成。
通信量 = 真实迁移字节；迁移段数 = 通信放大代理。
overlap ratio = 1 − T_pipe / (T_comm_alone + T_compute_alone)（R5 实现三项独立计时）。
Workload A 专属：hit rate、miss 字节/token、p50/p99 step。
扩展效率 = N 卡吞吐 / 单卡吞吐（4 卡窗口出）。

【9. 实验矩阵与消融开关】
开关：n_in_streams{1,2} × MoveStrategy{non-batched,fixed,adaptive} × overlap{seq,pipe}
      × queue{per-thread,wave} × 粒度{C4,固定页,固定1–4MB,自适应}
输入：arrival{steady,bursty,skewed/mixed} × hot{1,2,4}× × sparsity{4,16,64}KB × skew{bal,imb}
硬件：1（环回）/ 2（已出）/ 4（待窗口）。
必做消融（R4）：去 M1（n_in_streams=1）；去 M2（固定粒度）；去 M3（seq）；去本地优先（B 语义）。
建议：批大小曲线、hot 档位、per-thread vs wave。
不扫：语义模式、反压阈值、NVSHMEM、serving SLO、GNN/MoE 参数。

【10. 工程约束（七条，违反即死锁/假阴性/跨卡崩溃）】
1. 算通重叠只靠 event 依赖，不依赖跨 stream kernel 并发；队列+计算用单 kernel role-partition。
2. 迁移源必须驻留设备侧；host 数组不能作 HostStagedChannel 的 D2H 源
   （Workload A 例外：host pinned slab 本身就是源，通道对其只走 H2D 语义——由 slab_offset
   直供，不经过 D2H 段）。
3. 合成负载禁用随机字节→float（signaling NaN 位模式差异）；校验一律位级 memcmp。
4. 小总量会被自适应合并为单批；端到端 target_batches=8 保证流水窗。
5. CUDA event/stream 必须在 cudaSetDevice(src) 之后创建（跨设备 record 报
   invalid resource handle；单卡环回不暴露，跨卡必现）。
6. HostStagedChannel.submit() 会把上下文切到 src；调用方在 dst 流上启动计算 kernel 前
   必须 cudaSetDevice(dst)。
7. HostStagedChannel 析构会把上下文切到 src 销毁资源（现已恢复调用方设备）；
   任何「构造-使用-析构」块之后启动 kernel 前，仍必须显式 cudaSetDevice(dst)。

【11. 平台与执行策略】
共享集群：他人进程常驻（vLLM 驻留显存但 util=0% 时可用；util>0 或他人训练时禁用）。
监控线程 watch_gpu_window.sh 常驻（120s 轮询，日志 watch_gpu.log）。
数字层级：环回=机制证据；2 卡=论文主数字；4 卡=扩展性（专用窗口）。
任何新机器先跑 probe 复测通道再出数。

【12. 风险与止损】
不写成 QSA/HiSparse 跟跑；不滑回「泛稀疏」或 GNN；不模块堆叠；不抢 Shetty 单卡队列；
不复现 8×256K 容量数字；Portable 相对 B 无稳定收益即停扩。
新增：
- R1 修正后 C 仍 ≤A → 先查通信占比（加 payload/tasks），不得改结论口径（已解除：R3 全正收益）。
- 窗口长期不可得（>2 周）→ 4 卡矩阵降级，主结论挂 2 卡 + 机制层倍数。

【14. 推荐叙事（冻结）】
「Shetty 等解决了单 GPU 上可线性化、有进度保证的有界并发队列；但 LLM 稀疏注意力的持续
decode 把任务变成 host 完整 KV 与 GPU 热工作集之间的 miss 回填：静态划分与大同步在到达
偏斜、层间 locality 漂移和细粒度 PCIe 往返下放大通信、抬高尾延迟。我们提出不依赖 P2P 的
host-staged 多 GPU 运行时：miss 回填以双流流水化批传输执行，批粒度按待迁数据量自适应落在
通道饱和区，计算以 event 依赖与回填流水重叠；在 4×RTX 3090 上稳定提升吞吐、降低 miss
通信放大，并补齐突发/偏斜下的尾延迟与扩展效率评估。」
