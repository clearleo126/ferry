# HFE-EM ① OLMoE 路由 trace：热点持续性 / 四卡不均衡 / oracle 重布局 · 2026-11-07

目的：回答"专家热点是否持续、四卡 EP 的 rank 不均衡有多少可回收收益"。
模型 OLMoE-1B-7B-0924-Instruct（L=16, E=64, topk=8, 每专家 12.0MB），
单卡 decode 采路由，后处理成 EP=4 contiguous 放置。

代码：`tools/capture_moe_routing.py`、`tools/analyze_moe_routing.py`。
原始 npz / summary：`/data1/ferry_artifacts/hfe/routing/`。
矩阵：batch∈{1,8,32} × prompt_tokens∈{512,2048}，decode steps=256。
B_eff=18 GB/s（② 大块 greedy 并发 ~20 GB/s 的保守值）。

代价模型：层时间 = max_r(该 rank 上被激活的专家数) × c_exp；
c_exp 由同份 trace 的单卡步时反标定。相对量不依赖绝对 GEMM 效率。
均匀随机 top-8 子集的期望 Jaccard ≈ k/(2E−k) = 0.07。

## 读表

1. **热点不持续。** 最强的 b32 也只有 Δ32 Jaccard=0.32–0.34（随机 0.07，阈值 0.5）。
   b1 每步每层恰好抽 8/64，下一步集合基本洗牌（Δ1 也只有 0.25）。
   没有"搬一次、吃 32–64 步"的稳定热点。

2. **静态 EP 几乎已经均衡。** batch 越大越匀：b1 的 1.16 是矩阵里最不均衡的一档，
   到 serving 向的 b8/b32 变成 1.04 / 1.01。机制：b32 每层约 60/64 专家都被点到，
   四个 rank 的"激活专家数"没有可搬的差。OLMoE 训练带 `router_aux_loss_coef=0.01`，
   decode 路由本身就被拉平。

3. **窗口 LPT 在 W≥8 时毛收益已为负。** LPT 优化的是窗口内累计负载，层时间却是
   逐步 max_r(active)。窗口一加长，放置和逐步 max 错位，oracle 步时反而高于
   静态 contiguous。W=1 在 b1 有 +14% 毛收益，但每步搬 ~3.5–4 万专家
   （~450GB），净收益 −220%，回本 16–19 步——每步都搬，吃不到回本。
   b8/b32 的 W=1 毛收益已经掉到 +1% / −1%。

4. **和 ② 合在一起。** 即便把 B_eff 从 18 GB/s 改成短突发 20 GB/s，也救不了
   负的毛收益；改成持续限速 2.5–3 GB/s 只会让净收益更负。调度"何时搬、搬哪个"
   在这份 OLMoE decode 上没有正的对象。

---

## 对 HFE-EM 的收紧

本实验把"存量 decode + 四卡 EP + 专家权重一次 H2D"这条线，在
**OLMoE-1B-7B / top-8 / 64 专家 / aux-loss 均衡** 上做成了负结果。
负结果有效：不是测错，是这台模型、这个 decode 批次下没有可回收的
rank 不均衡。

③ 简单策略对照在 OLMoE decode 上预期仍是负，不建议用同一模型做正例。
若还要追专家迁移，换路由更尖的对象，例如：

- 更大专家数、更小 top-k（Mixtral 8×7B top-2，DeepSeek-V2/V3 160+/top-6）
- 明确报告过推理 EP 不均衡的 serving 痕迹
- 或放弃"搬专家"，把 ② 的争用测量收进 Ferry 的共享通道成本，而不是新主线
