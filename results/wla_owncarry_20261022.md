# 按请求归属 carry（own-carry）运行时落地：机制验证与首轮实测

日期：2026-10-22；平台：本机 **2×3090（GPU1/GPU2，GPU0 被他人占用）**，PCIe4。
参数：`--requests 16 --prefix-group 4 --prefix-steps 8 --kv-mode delta`，seed 42，
引擎 = C（`ferry-C`）/ E（`costaware-E`），对照 = RR（own-carry 不变项 = 噪声基准）。
日志：`results/wla_owncarry_20261022/{inter,reps}/`。

## 1. 实现了什么

`--own-carry`（默认关，`MissSpec.own_carry`；快照尾部追加 `FTR4`）：

- 逐 (卡, 组, 层) 的**块归属掩码**（uint32，bit = `r % prefix_group`）：
  `kv_touch` 置位、逐出/裁剪清条目、请求离开（被窃走/完成）清位。
- `steal_from` 三处同口径：成本模型用 `kv_live_owned`（独占块数）、传输枚举只发
  独占块、`kv_handoff` 改为**合并**语义（只并入独占块，不再整组覆盖消费卡镜像）。
- 判定：`mask == bit(r)` 独占 → 搬；含其他位 → 共享 → 留 victim、消费卡按 miss
  回填；`mask == 0` → 死块 → 不搬。
- 守卫：仅 `delta`/`delta-naive`；`prefix-group <= 32`（掩码位宽）。

## 2. 单次运行**不可复现**（本轮最重要的方法论修正）

同一配置连跑两次（`grp1_grp` vs `grp1_grp_b`）：C 迁移字节 **20.4 vs 48.9 MB**。
原因是运行时按真实墙钟推进 tick，抢锁/通道完成时刻不同 → 决策点数量本身会变。
⇒ 之前所有"逐位回归"只对**反事实回放**（纯 CPU）成立；**GPU 实跑必须反复数、
且必须交错 A/B**（顺序跑会被时钟漂移污染：`grp1` 那批 RR 不变项从 203.0 漂到
211.3ms，+4%）。

本报告的 `inter/` 为 6 对**交错**运行（A,B,A,B,…），`RR` 作噪声基准。

## 3. 结果（6 对交错，中位数）

| cap-mode | 臂 | 迁移字节 | refill | 净字节 | C makespan Δ | RR Δ（噪声基准） |
|---|---|---|---|---|---|---|
| group  | C | 15.0 → **6.3 MB**（−58%） | 246.2 → 257.6（+4.7%） | **+2.8 MB** | +12.5 ms | +8.3 ms |
| group  | E | 15.0 → **0.0 MB**（−100%） | 246.0 → 244.7（−0.5%） | **−16.3 MB** | +16.8 ms | +8.3 ms |
| perreq | C | 70.7 → **7.0 MB**（−90%） | 208.2 → 216.7（+4.1%） | **−55.2 MB** | −0.1 ms | +3.1 ms |
| perreq | E | 15.0 → **2.9 MB**（−81%） | 215.5 → 226.9（+5.3%） | −0.7 MB | +12.5 ms | +3.1 ms |

读法：

1. **机制按模型工作**：迁移字节 −58~−90%，refill +4~5%。这正是 22.6 离线预演的
   `A = excl + 懒回填` 交易（离线：传输 −15.7MB、回填 +4.5MB / 决策；实测 group 臂
   C：−11.7MB / +11.4MB，量级一致）。
2. **本地 makespan 看不出差异，且不能判负**：RR 不变项的配对 Δ 中位数本身就是
   +3~+8ms（= 噪声尺度），所有臂的 Δmakespan 都落在噪声里。本地 15–70MB 的迁移
   在 17.6 GB/s 下只有 1–4ms，占 150ms 的 1–3% ⇒ **平坦高原的又一次复现**。
3. **不是无条件划算**：group 臂 C 的净字节反而 **+2.8MB** —— 留在 victim 的共享块
   没有被留下成员复用，纯粹变成回填。**归属 carry 的收益取决于"留下的人会不会
   再用"**；perreq 臂（组被摊开、共享块多数是搬迁者自己还要用的）才是净赚
   （C：−55.2MB）。
4. **额外收益未计入上表**：旧语义 `kv_handoff` 是**整组覆盖**消费卡镜像，组已被
   拆开时会抹掉消费卡上同组其他成员的缓存；合并语义不再抹。本轮把它和"只搬独占
   块"捆在一起改了（两处效应未拆开，需单独 ablation）。

## 4. 局限

- 2 卡、单 seed、C2 合成 trace（`sel=64, slab=192`）；6 对交错的噪声尺度仍有 ±30ms。
- 在线归属 = **过去触碰**（"本卡该组还有谁碰过"），离线 22.6 的 excl% 是
  **未来 h 步前瞻**（"将来只有谁会选"）。两者不同口径：合成 trace 的 id 空间只有
  192 个，组内 3 个 peer 几步就覆盖全部 ⇒ 在线独占率趋近 0（group 臂 E 迁移字节
  = 0.0 就是这个退化），**离线 11–17% 的独占率不可在线复现**。
- 因此 22.6 的"B/A 6–9×"是 oracle 上界；可实现版本对应的是上表。
- 未做：merge-only ablation、真实 trace 快照、多节点带宽下的同一对比。

## 5. 复现

```bash
./build/run_wla_multigpu --gpus 1,2 --requests 16 --prefix-group 4 --prefix-steps 8 \
  --kv-mode delta --cap-mode perreq --own-carry
```
