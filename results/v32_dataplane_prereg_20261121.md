# v32 数据面预注册：共享 host 介质的争用放大 × ld.global.nc/DMA 切换边界（2026-11-21，跑前写死）

## 0. 定位（与被判死的两条支线划清边界）

主线（【27】–【32】）是**控制面**：κ 门控、容量加权窃取、迁移范围选择。
本支线是**数据面**：miss 从 host 到卡的这段路怎么走。它自带结论，不并入 κ 框架。

三条已关掉的路，本支线不得重走：
- 【29】HFE-EM：专家权重迁移，收益空间与争用两端都不成立。
- 【30】DMA × CUDA Graph：机制成立但 replay 开销吃掉收益；E11 证明 KV 回填上
  **批量 loop 就比图快 17%** ⇒ 本支线**不再碰 CUDA Graph**，只用 CE 与 SM 两条路。
- AI 侧提到的"单步有界 fetch 原语"：本支线**不造新原语**，只做路径选择规则。
  理由：E9 已测出分支固定开销 1.35 µs/分支，任何"新原语"都会撞上【30】的同一堵墙。

与外部工作的差异（必须写进论文相关工作，否则会被判重）：
- HiSparse：单卡层次化稀疏 KV + fused kernel + exact prefetch；其 IO 集成就是
  "async memcpy + 分块重叠" ⇒ **本支线的 CE 臂不是新机制，只是它的基线**。
- InfiniGen (OSDI'24)：host KV + 前瞻预取；同样是单卡、单进程视角。
- ThunderEP：SM 路径 vs DMA 的算法层冗余（2(N−1)S → N·S）**不存在于 KV miss 流**
  （miss 字节已是必要的，没有中继跳）。能借的只有"哪条路"这一层。

本支线只主张两件事：
1. **争用放大**：多卡共享 host 介质时，两条路径的劣化形态不同（延迟放大 vs 带宽均分），
   因此在**未饱和**负载下就已出现可测的税。
2. **边界移位**：单卡 profile 得到的切换边界，在多卡争用下系统性偏移；边界必须用
   在线可观测量选，不能用静态 profile 常数。

## 1. 仓库内已确立的事实（本轮不重测，只引用）

| 事实 | 数值 | 来源 |
|---|---|---|
| 单卡 CE H2D 峰值 | 25.2 GB/s（1 个 copy engine，多流不叠加） | E4 |
| 单卡 SM 读 mapped host 峰值 | 20.9 GB/s（并发拷贝 kernel）；18.6 GB/s（§12.2 口径） | E4/§12.2 |
| CE 背景搬运对前台 p99 | 23 GB/s 时 **+0.0%**（近零税） | E4/E10 |
| SM 背景搬运对前台 p99 | ≥4 GB/s 即 **+30%**，9–16 GB/s 时 p50 +31–35% ⇒ **阶跃，不是线性** | E10 |
| 16KB 页回填：每页 sync vs 每批 sync | 117.1 → 38.8 µs/步（−67%） | E11 |
| 四卡拓扑 | 本机 4×3090，PCIe4 x16/卡，无 P2P，双路 Xeon 4314，NUMA 0=GPU0/1、NUMA 1=GPU2/3 | 本机核实（2026-11-21） |
| 迁移路径有效带宽 | 17.6–17.9 GB/s（x16 卡对，24MB 端到端） | 平台记录 |

**未知量（本支线要补的）**：
- 4 卡**聚合** host 读上限（单卡 25 GB/s 是否线性叠加到 100 GB/s，还是被 root complex 封顶）；
- 跨 NUMA 分发时的额外税（本机 GPU0/1 与 GPU2/3 分属两个 socket，此前所有实验都在单 NUMA 域内）；
- 未饱和负载下的**延迟**税（E10 只测了同卡 SM 拷贝 kernel 的**前台**税，没有测跨卡、也没有测依赖加载延迟）；
- in-kernel 依赖加载的暴露时间随 batch/k/miss 的曲面。

## 2. 负载包络（先算清楚：这一节决定主张生死）

每卡 miss 需求（GB/s）= `R × s × L × kv_bytes × m / T`
（R=卡上并发请求，s=每请求每层选中 token 数，L=28，kv_bytes=2048 B/token/layer
= 4 KV heads × 128 × 2 × fp16，m=miss 率，T=step 时间）

| 档 | 配置 | 每卡 | 4 卡聚合 | 说明 |
|---|---|---|---|---|
| trace | R=12, s=64, m=0.16, T=45ms | **0.16 GB/s** | 0.6 GB/s | 真实 trace（qwen7b_g4_quest，hit 0.86） |
| trace@b1 | R=1, s=64, m=0.16, T=19.6ms | 0.03 GB/s | — | 单请求口径 |
| stress | R=24, s=256, m=0.50, T=60ms | **2.9 GB/s** | 12 GB/s | 128K context、k=64 页、batch 24 |
| aggressive | R=32, s=512, m=0.60, T=60ms | **9.4 GB/s** | 38 GB/s | 极端但物理可行（host 235GB 可容纳） |
| extreme | R=64, s=512, m=0.80, T=80ms | 18.8 GB/s | 75 GB/s | 逼近单卡链路上限 |

**先写死的推论**（不许事后改）：
- 真实 trace 负载只有单卡链路的 **0.6%**、单卡 SM 阶跃阈值（4 GB/s）的 **4%**
  ⇒ **在 trace 负载下，争用与路径切换都不会有任何可测收益**。本支线的所有主张
  必须落在 **≥2 GB/s/卡（≥12× trace）** 的档，且必须在论文里如实标注这个倍数。
- 若"128K 长上下文 × 高并发"这一档被认为不现实，则本支线的**正确结论是边界注记**，
  不是系统贡献。这个判断不由实验结果决定，由 §7 的止损条款决定。
- 与【31】的 `B≥10 GB/s` 是同一数量级：**主线赢的场景本来就是高带宽需求场景**，
  数据面问题只在同一批场景里出现——这构成两条线合在一篇论文里的合法性。

## 3. 装置（新文件，不复用 bench_graph_dma 的图路径）

新二进制 `src/benches/bench_miss_contention.cu`（CMake target 同名）：

- **每卡一个 host 线程**：各自 `cudaSetDevice` + 独立 stream，避免默认流跨卡串行。
- **共享 pinned 池**：`cudaHostAllocMapped`，分配前用绑定到指定 NUMA node 的线程
  first-touch（`--host-numa 0|1`），从而可切换"同 socket"与"跨 socket"两种拓扑。
- **三件事一台装置**：
  1. `lat`：mapped host 上的**依赖加载延迟探针**（指针追逐，每卡 256 线程 × 4 链），
     与其它卡的流量并发，输出 p50/p99 每跳延迟。
  2. `agg`：每卡按目标速率拉流（`sm` = 读 mapped host 的拷贝 kernel；`ce` =
     `cudaMemcpyAsync` 分块），输出达成带宽、聚合带宽、公平性（窗口内 max/min）。
  3. `fg`：前台 attention 代理（QK→softmax→PV over 常驻页，fp16），输出 step p50/p99。
- **速率控制**：`--rate GB/s`（每卡目标），实现为 credit 窗口（每 1ms 放行 `rate×1ms`
  字节），而不是"能跑多快跑多快"，这样才可做"同速率、不同卡数"的对照。
- **突发模式**：`--burst 1` 让 4 卡用同一 epoch 起点同步起爆（模拟 TP 耦合同步 miss），
  vs `--burst 0` 各自相位错开。
- **正确性**：每配置结束时校验目标缓冲区内容（防"没搬也算带宽"）。

## 4. Task A：争用放大

### 4.1 矩阵（n=3 交错，2 seed）

| 轴 | 取值 |
|---|---|
| 卡数 n | 1 / 2 / 4 |
| 每卡速率 | 0.5 / 1 / 2 / 4 / 8 / 16 GB/s |
| 路径 | sm（mapped 读）/ ce（memcpy） |
| host 池 NUMA | 同 socket（GPU0/1 用 nuid 0）/ 跨 socket（GPU2/3 用 nuid 0） |
| 突发 | 错相（0）/ 同步（1） |
| 前台 | 无 / 常驻 attention 代理 |

主表 `agg`：每格报 单卡达成、聚合、公平性、前台 p99 税、每跳延迟 p50/p99。
粗矩阵 3×6×2×2 = 72 格；突发轴与 NUMA 轴只在 n=4、rate∈{2,4,8} 上加（+24 格双跑）。

### 4.2 预注册假设（允许被证伪）

- **H-A1（聚合上限）**：`ce` 聚合在 n=4 时 ≥3.0× 单卡（≈70 GB/s 以上）⇒ 各卡链路基本独立，
  root complex 不封顶；若 <2.5× 则存在共享瓶颈，且这就是最强的"消费级放大"证据。
  `sm` 聚合上限预测低于 `ce`（SM 路径每卡自身先饱和于 ~20 GB/s）。
- **H-A2（延迟放大）**：n=4、每卡 2 GB/s（聚合 8 GB/s，**链路利用率仅 8%**）时，
  依赖加载 p50 延迟相对 n=1 上升 **≥20%**；跨 NUMA 再叠加 **≥40%**。
  这是本支线的核心机制假设：**争用放大是延迟的，不是带宽的。**
- **H-A3（前台税）**：同速率下 n=4 的 SM 背景前台 p99 税 ≥ 单卡的 1.5×；
  CE 背景税在 ≤8 GB/s/卡时仍 <5%（延续 E10 的"CE 近零税"到多卡）。
- **H-A4（突发）**：同步起爆相对错相，在**相同平均速率**下 p99 税 ≥2×。
- **公平性（探索性，不预注册方向）**：root complex 仲裁是否让某卡长期吃亏
  （窗口内 max/min 达成带宽比）。没有先验，只报数。

### 4.3 杀门

若同时满足 **(a)** `ce` 聚合 ≥3.5× 单卡、**(b)** n=4/2 GB/s 时延迟上升 <10%、
**(c)** 前台 p99 税 <5% —— 判"**共享介质争用不成立**"，A 退化为"四卡可独立打满"的
正面平台结论（对主线有用：说明迁移通道不会互相踩），B 只保留单卡边界，C 不开工。

## 5. Task B：ld.global.nc 与 DMA 的切换边界

### 5.1 四臂（同一 attention 代理，只换 miss 数据的来路）

| 臂 | 语义 | 对应 |
|---|---|---|
| `dep_sm` | attention kernel 内直接 `__ldg` mapped host 的 miss 页，**依赖加载、无预取** | HiSparse fused（no-prefetch 下界） |
| `dep_ce` | 本步先 `memcpy` 到 device scratch，再算（**无重叠**） | 朴素 DMA，基线 |
| `pf_ce` | 上一步预测的 miss 页由 CE 预取到 scratch，本步 attention 读 device | HiSparse IO 集成（最佳形态） |
| `pf_sm` | 同上，但预取用 SM 拷贝 kernel | ThunderEP 的 SM 路径 |

**预取覆盖率 `--cover` ∈ {0.66（真实 trace 步间复用）, 0.80, 1.00（oracle 上界）}**。
不许把 `pf_*` 跑成 cover=1 当主结果（那是上界，不是可达值）。

### 5.2 矩阵

- 阶段 1（单卡、无背景）：R ∈ {4,8,16,32,64} × s ∈ {64,128,256,512} ×
  `dep_sm/dep_ce/pf_ce/pf_sm` × m ∈ {0.16,0.60}，页 8KB（真实 c4），cover=0.66/1.0。
  128 格 × n=2。
- 阶段 2（只在交叉区）：把阶段 1 中"两臂差 <25%"的格子挑出，加
  m ∈ {0.16,0.35,0.60,1.00} × 页 ∈ {8,16,64}KB。
- 阶段 3（耦合）：对阶段 2 的交叉区，跑 n ∈ {1,2,4} × 每卡 2 GB/s 背景（A 的 `ce` 路径）。

### 5.3 预注册假设

- **H-B1（暴露时间）**：`dep_sm` 的暴露时间 ≈ `bytes / B_lat`，其中
  `B_lat ≈ 并发独立加载数 × 64B / 延迟`；R 翻倍、暴露减半（直到带宽界）。
  s 增大时线性上升。⇒ 预测 R≤8、s≥256、m≥0.6 的格子**延迟界**（暴露 > 计算时间）。
- **H-B2（交叉）**：`pf_ce` 赢 `dep_sm` 的条件是
  `cover × bytes / B_ce + fixed < bytes / B_lat`（且 CE 的双次触碰已计入）。
  预测交叉在 **R≥16、s≥256、m≥0.6、cover≥0.66**；`dep_sm` 在 R≤8 全胜。
- **H-B3（规则的余地 = 主杀门）**：trace 包络（R=12、s=64、m=0.16）落点处
  `dep_sm` 领先 ≥2×，且交叉区**不覆盖**任何 trace 邻近格 ⇒ 规则在真实负载下无事可做。
  只有交叉区落进 stress 包络（R 16–32、s 256–512）才算有规则空间。
- **H-B4（耦合，本支线的核心主张）**：加入 n=4 争用后，交叉点向 CE 侧移动
  **至少一个网格步**（R 方向 ×2 或 s 方向 ×2）。若不移动，A 与 B 是两个独立测量，
  "边界随争用移位"这个卖点取消。
- **H-B5（预取覆盖可在线预测）**：`--cover` 用上一步 selection 重叠率在线估计时，
  预测值与 oracle 实际覆盖率的误差 ≤10 个百分点。

## 6. Task C：路径选择规则（自带，不并入 κ）

**仅当 H-B3 与 H-B4 同时通过才开工。**

规则输入（全部在线可得）：
1. 本步 miss 字节估计 `M`（复用 `--len-est/--miss-est` 的在线口径）；
2. 上窗口实测 CE 达成带宽 `B_ce`；
3. 并发取数卡数 `n`；
4. 上一步 selection 重叠率 `cover`（预测预取覆盖率）；
5. 卡上并发请求数 `R`。

决策：`choose CE iff M/B_ce + fixed(n) < M/B_sm_eff(R, n)`，其中
`B_sm_eff` 由 A 测得的延迟模型代入（**不许用单卡 profile 常数**）。

验证：
- 三策略（always-SM / always-CE / rule）× 三档负载（trace / stress / aggressive）
  × 2 seed，每档 512 步；
- **影子决策**：同状态只换输入重算路径选择，累计误切换率（该 CE 走了 SM / 反之）；
- 端到端判据：rule 的 p99 step 相对**两个固定臂中较好者**改善 ≥10%，且在
  ≥2 档负载上成立、2 个 seed 同向。
- 杀门：若 rule 只在 oracle cover 下赢 ⇒ 判"规则不可落地"，退回 A+B 的刻画。

## 7. 判定与止损（先写）

1. **A 死**（§4.3 三条同时成立）⇒ 只发"四卡 host 通道可独立打满"，不进系统章节。
2. **B 的 H-B3 死** ⇒ 单卡边界作为机制注记（补 E4/E10 的 KV 版），不做规则。
3. **H-B4 死** ⇒ A、B 两条独立测量，主线故事退化为"两条路径的代价图"，不是"边界移位"。
4. **全部死** ⇒ 本支线按【29】【30】纪律关闭，剩余价值 = 论文里一段
   "为什么 HiSparse 式的 host link 不是可优化瓶颈"的定量边界，**不改主线**。
5. 统计纪律：所有主张用 **配对差 + 确定性字节/事件账**；3090 的 makespan 噪声
   ±10–25%，p50/p99 用 n=3 中位；n=3 只作筛选，入正文需 n=5 复跑。

## 9. 证据边界（随数字一起引用）

- 本机是**双路 Xeon 服务器**（12 通道 DDR4），不是消费级 dual-channel；结论里的
  "消费级"只指 **无 P2P + PCIe 扇出 + host-staged**，不指 DRAM 带宽。
  若要在真消费级主板上外推，必须补一次 P0（可作为租卡敏感性，非必需）。
- 前台是合成 attention（QK/softmax/PV），不是 vLLM 的 paged attention + 量化；
  绝对 step 时间不可换算成 TPOT。
- 页粒度 8/16/64KB 覆盖 c4 与合并粒度，但真实引擎的对齐/装箱可能更差。
- 延迟探针与真实 in-kernel 依赖加载的并发度不同（探针 256 线程固定），
  只用于"争用是否放大延迟"的方向判断，不用于绝对带宽换算。
- 3090 的 copy engine 只有 1 个/卡；4090/H100 上 CE 并行度更高，结论需标注平台。
