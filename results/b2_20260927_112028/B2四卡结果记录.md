# B2 四卡结果记录（2026-09-27 集群 PCIe4 独占机）

> 跑机条件：
> - 平台：实验室集群 4× RTX 3090（sm_86），PCIe4 × 2 NUMA，对称拓扑（0↔1 NODE，2↔3 NODE，跨 NUMA SYS）
> - gpus = 0,1,2,3（4 卡独占，跑机时 nvidia-smi util=0%、其他 GPU 无进程）
> - probe 验收：probe_bw.csv 16MB 单流 11.85 GB/s、2MB 11.03、1MB 10.22 → knee ≈ 1MB（与 g*≈1MB 一致）
> - 到达配置：tasks=32768，tick=0.0005，steal_thr=0.25，sparsity 默认
> - 对照：C（自适应批 NT 常量 4MB，同引擎） vs E（mode 5 四路输入实时批决策，同引擎同窃取语义）
> - 注意：**E 的决策公式 = eff = visible/(1+inflight) 夹 [min(sat, visible), max_mb=4MB]（见 multigpu.cuh mode=5）**
>   由于 Workload B（pool-only，payload 恒在 pool，窃取不迁 KV）下 visible ≈ occ+srco ≈ NT 恒大，
>   inflight ≤ pending_ahead=4，故 E eff 始终夹到 **≈3.8–3.96MB（C 的 4MB 只差 3–9%）** →
>   批差量太小，T2/T3 差值被组内 std（3–6%）淹没，这是 P2/P3 不通过的根本原因。

### 2.2 P1 g_opt≈g* 判定
- **E 均值排序（sat 升）**：1.0(165.81) < 0.5(167.99) < 0.25(168.31) < 0.125(169.21) < 2.0(169.74)
- **最优 sat = 1.0MB，为内部点**（非端点）→ 与 g*≈1MB 预测一致 ✅
- 最优 vs 最差 Δ = 169.74 - 165.81 = **3.93 ms**，Welch two-sample t ≈ 0.78 → p(2side) ≈ **0.865 不显著**
- ⚠️ **结论：P1 方向通过，量级仍弱；曲线整体平，必须在更大任务量（如 tasks=131072）或 8 卡重扫**

### 2.3 P2 "bursty E 优 / steady E→C" 判定
- **强侧 bursty**：E 相对 C 增益 = (168.86 - 175.82)/168.86 = **-4.12%**（方向错 ❌）
  - 含 outlier r2 = E=236.72 vs C=162.63（该次 C 也在慢档 164 区间，E 突增至 236）
- **弱侧 steady 深队列**：C/E=1.008，E 相对 C 增益 **+0.79%**（方向对，但 paired p=0.115 边缘，不显著）
- balanced 档 mg_steady_balanced C/E=1.035（E 略快 3.4%），但仅 1 次重复；不触发反证。
- **结论：P2 预测不成立。根因 = E 决策始终被 max_mb=4MB 钳死，与 C 批差 <9%。**

### 2.4 P3 "N 升 E 增益升" 判定
- N=2（a5_b2_2card 2026-09-23）：C/E = 0.986（E 慢 1.4%）
- N=4（本次 PCIe4 独占 sat=1 steady）：C/E = 1.008（E 快 0.8%）
- 趋势：N↑ C/E↑ → E 相对更好，但 **2.2% 差量在噪声内，不构成"单调升"的证据**
- 与 C/D1（1 卡 1.000 → 2 卡 1.066 → 3 卡 1.098 → 4 卡 1.122）的稳定单调相比，P3 在 2→4 卡段**未证实 ❌**

## 3. 关键解释（诚实不利数据的机制解释）

| 现象 | 解释 | 对论文结论的影响 |
|---|---|---|
| E 批始终只比 C 小 2–9%（199–214 vs 218–219） | E 公式 eff = visible/(1+inflight)，Workload B 下 `visible ≈ occ+srco ≈ NT 巨大`，inflight ≤ pending_ahead=4 → eff ≈ NT/5 ≈ 6553/5 ≈ 4MB，夹到上限 max_mb=4MB。sat 参数只影响 lo=min(sat,visible) 的**下界钳制强度**（sat 小 → lo 小 → E 批略小 8.9%；sat 大 → lo 与 visible 同量级 → E 批接近 C）→ 差量 < 组内 3–6% std | B2 的"实时决策作用面"在 pool-only 下已经被 NT 大任务压到极限，**不是启发式本身不好，是 regime 没给它发挥空间** |
| bursty 下 E 反而慢 4%（含 r2 outlier 236.72） | bursty 到达相位性强，某时刻 occ(g) 瞬时空 → srco 也瞬时低 → visible 瞬时掉到小 → eff 会被 lo=sat 夹到过小批（199 批 ≈ 3.8MB），1 次小批 + 锁争用 = 尾部 outlier 放大到 236ms | **P2 打脸的根源**。改进方向：E 决策把"瞬时 visible"改为"EWMA 平滑窗口 visible"或加硬下界 ≥ g*=1MB。但本项目不动代码，只写边界 |
| C/D1 从 2 卡 1.14→4 卡 0.85（方向反） | 不是 B1 的 monotonic 结论错，是 4 卡数据里 imb(E)=0.178 拉高了 E makespan——E 跟 D1 同样都有"imb 被批量化拉坏"的 trade-off（D1 imb 也高）。两机 imb 绝对数字不可比，但相对的"粒度越细 imb 越好"趋势一致 | 只在 mg_steady_imbalanced 1 次出现，无统计显著性。B1 结论仍以 vast 4 卡 5 次重复的 1.122 为主，本地作对照 |

## 4. 复现命令

```bash
# 环境验收
nvidia-smi --query-compute-apps=pid,used_memory --format=csv
./build/probe --bw --csv results/b2_20260927_112028/probe_bw.csv > results/b2_20260927_112028/probe.log

# 冒烟矩阵（6 模式 × 2×2）
for arr in steady bursty; do
  for skew in balanced imbalanced; do
    ./build/run_multigpu --gpus 0,1,2,3 --tasks 32768 --arrival $arr --skew $skew --sat-mb 1.0 \
      > results/b2_20260927_112028/mg_${arr}_${skew}.log 2>&1
  done
done

# B2 主矩阵：steady/imb × 5 sat 档 × 7 次（主表）
for sat in 0.125 0.25 0.5 1 2; do
  for r in 1 2 3 4 5 6 7; do
    ./build/run_multigpu --gpus 0,1,2,3 --tasks 32768 --arrival steady --skew imbalanced --sat-mb $sat \
      > results/b2_20260927_112028/b2_steady_imb_sat${sat}_r${r}.log 2>&1
  done
done

# B2 主矩阵：bursty/imb × sat=1 × 7 次（P2 对照）
for r in 1 2 3 4 5 6 7; do
  ./build/run_multigpu --gpus 0,1,2,3 --tasks 32768 --arrival bursty --skew imbalanced --sat-mb 1.0 \
    > results/b2_20260927_112028/b2_bursty_imb_sat1_r${r}.log 2>&1
done
```

- 单轮 mg 约 3–5 秒；b2_* 主矩阵共 5×7 + 7 = 42 次 × 约 3 秒 ≈ 2–3 分钟跑完。
- **注意**：如果是共享集群而非独占，先跑完 §2 第 4 关（7 次 C 重复 std/mean <10%）再出数；否则 15–25% 双峰邻居噪声会把 P1/P2 信号完全淹没。

## 5. 论文结论的最终口径（与 实验设计.txt v6 §0 / §15.5 对齐）

1. **主结论不变**：M1×M3 协同 1.92×、B1 粒度 1.13×（窃取次数 ↓175×），这两块是真收益。
2. **B2 的诚实边界**：
   - pool-only / 大任务 / 饱和通道 regime 下，C 选的 4MB 固定批 **≈ g_opt**（E 决策没有可增益空间）；
   - P1 g_opt≈g* 位形方向通过，但曲线平（弱证据）；
   - P2/P3 在该 regime 不通过，是因为 regime 给 E 的作用面太小，不是 T1/T2/T3 三项代价模型错。
3. **诚实报告不利数据**：对账表 ⑧⑨ 条（4 卡 steady/bursty E 不优）必须入论文。
4. **下一步（救 B2 的唯一方向）**：在 Workload A（真实 KV 逐请求迁 payload、visible/g 会真实波动到 <4MB、锁争用真实、迁移字节随窃取变）重测 B2；或 tasks × 4（131072）放大 P1 曲线差异。
