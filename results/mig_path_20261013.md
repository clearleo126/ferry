# 小实验 A · 迁移路径选择：双跳携带 vs host 真值直发 · 2026-10-13 · 集群 PCIe4 4×3090

目的（主动负载策略创新点验证）：回答"迁移到底该走哪条路"——
现状 = victim GPU →(D2H)→ host pinned →(H2D)→ consumer 双跳；
假想 = host 真值 →(H2D)→ consumer 单跳直发。
若单跳显著更优且 host 副本有效，"请求归属变化 ≠ 热集整体搬家"
就有量化支撑（迁移内容/路径应成为决策变量，而非固定双跳）。

代码：`src/benches/run_mig_path.cu`（commit 见本日期提交）。
参数：GPU0→GPU1，reps=30（warmup 3），c4=16KB，通道 = 生产同款
HostStagedChannel（4 slot × 4MB × 双入流）。原始日志：本目录 mig_path.log。

## 前提核验

`d_src == h_slab` 整段 memcmp **PASS** —— WlA 数据面中 host slab 是唯一
真值（GPU cache = refill 副本，attn 写 d_out scratch 不回写），双跳的
D2H 分量在合成场景是**冗余搬运**。⚠️ 真实稀疏 decode 中新生成 token 的
KV 会先落 GPU、再写回 host ⇒ host 副本对"新 token 块"可能滞后，
线上系统须按块级版本/脏位判定有效性（本实验不覆盖该情形，如实声明）。

## 结论（两条，方向相反——这是非平凡结果）

1. **整段（full）：host 真值直发赢 20–49%**。机理：双跳虽经 PCIe 全双工
   流水（D2H/H2D 双流并发），ring 串行依赖使有效带宽 17.9–20.1 GB/s <
   单跳 H2D 25 GB/s；且 host 直发**不占用 victim 的 PCIe 上行**
   （该上行同时服务 victim 自身 miss 回填的反向流量与迁移 D2D，见
   小实验 B 的干扰测量）。
2. **增量（delta，散布槽）：双跳反而赢**。机理：host 侧没有 GPU 侧
   gather 的并行度——散布 16KB 槽的 CPU memcpy 是瓶颈（512 槽 8MB 时
   host 侧压实 ~1.2ms vs GPU gather ~0.1ms），双跳的 GPU gather +
   通道传输只需 0.59ms。host 直发的收益被 CPU 压实吃光。

⇒ **迁移路径不该写死，应按（内容布局 × 驻留率 × 链路争用）联合决策**：
整段/高驻留 → host 直发（单跳、省 victim 上行）；散布低驻留 → victim
侧 gather + 双跳。这正是"主动负载策略"的第三个决策维度（归属 ×
时机 × 路径/内容），且两条边界都有实测数字。

## 边界与不外推声明

- 合成场景 host 副本恒有效；真实系统的脏块（新 token KV）须版本判定，
  未测。
- host_delta 的 CPU 压实是单线程实现；多线程/预压实 host 布局会移动
  交叉点（更偏 host 直发），本实验取保守实现。
- 数字层级：集群 PCIe4 4×3090 单次基准；比值（host/dual）反映机制，
  跨平台须复测（vast PCIe3 待做，带宽收窄时 host 直发省的下行时间
  占比更大，交叉点应更偏 host）。
