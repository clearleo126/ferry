# 拓扑验收记录 — 4×RTX 3090（vast.ai 实例）

- 日期：2026-09-23
- 机器：vast.ai On-Demand 实例，4×NVIDIA GeForce RTX 3090 24GB（`GPU-0a66778f`, `d45bf8ec`, `8ad6666a`, `4354b5f6`）
- 驱动 / CUDA：570.133.20 / CUDA 12.8.93（nvcc 12.8）
- 构建：`cmake -S . -B build -DCMAKE_CUDA_ARCHITECTURES=86 && cmake --build build -j8`（sm_86）
- 原始数据：[acceptance_data.csv](acceptance_data.csv)、[topo.txt](topo.txt)、[probe.txt](probe.txt)、[bw.txt](bw.txt)、[bwscan.txt](bwscan.txt)
- 对应文档：[说明文档（大模型运行前必看）.md](../../说明文档（大模型运行前必看）.md) §2 三关、[实验设计.txt](../../实验设计.txt) §0/§11

> **一句话结论**：本机与集群/实验室 4×3090 **互联类型一致（无 NVLink、4 卡全 x16 直连、只出现 PHB/NODE）**，
> 但 **PCIe 代数不同 —— 本机 Host Max = PCIe 3.0，集群参考值是 PCIe 4.0**，导致 host-staged 绝对带宽
> **恰好减半（≈0.50×）**。按说明文档 §2 第 3 关「偏差 >20% → 数字不可混用、退租换机」的判据，
> 本机的**绝对吞吐数字不可与 2 卡主数字混用**；但机制比值（bench_comm ratio）仍然保留。

## 1. 互联矩阵（`nvidia-smi topo -m`）

```
        GPU0    GPU1    GPU2    GPU3    CPU Affinity    NUMA Affinity   GPU NUMA ID
GPU0     X      NODE    NODE    NODE    0-31    0               N/A
GPU1    NODE     X      NODE    NODE    0-31    0               N/A
GPU2    NODE    NODE     X      PHB     0-31    0               N/A
GPU3    NODE    NODE    PHB      X      0-31    0               N/A
```

- **无 `NV#`**（无 NVLink）→ 满足论文前提「host-staged，跨卡必经 host 内存」
- 逐对互联类型：GPU2↔GPU3 = `PHB`；其余两两 = `NODE`；无 `PXB/PIX`（无 x4 挂 switch）
- 4 卡 `CPU Affinity` 均为 `0-31`，`NUMA Affinity` 均为 `0`

判定：互联类型只出现 `PHB` / `NODE`，**第 1 关（互联类型）通过**。

## 2. PCIe 链路（`nvidia-smi --query-gpu=pcie.link.*`）

| GPU | PCI Bus ID | link width (当前/max) | link gen (当前/max) | Device Max gen | Host Max gen | 显存 |
|---|---|---|---|---|---|---|
| 0 | 00000000:46:00.0 | 16 / 16 | 1 / 3 | 4 | **3** | 24576 MiB |
| 1 | 00000000:81:00.0 | 16 / 16 | 1 / 3 | 4 | **3** | 24576 MiB |
| 2 | 00000000:C1:00.0 | 16 / 16 | 1 / 3 | 4 | **3** | 24576 MiB |
| 3 | 00000000:C2:00.0 | 16 / 16 | 1 / 3 | 4 | **3** | 24576 MiB |

- 4 卡 **全部 x16**（max width = 16）→ 满足说明文档 §0「4 卡全部 x16 直连 CPU」
- **卡支持 PCIe 4.0（Device Max = 4），但主机侧上限 = 3（Host Max = 3）** → 链路只能跑 **PCIe 3.0 x16**
- 空闲时 `gen.current = 1`（省电降速）；打流时实测升到 **3**（已确认能跑满 gen3，不是链路没协商起来）
- 卡型 sm_86，与集群 3090 同代

## 3. CPU / NUMA

- CPU：AMD EPYC 7282 16-Core（16C/32T），**单 socket**，`NUMA node(s): 1`
- 4 卡同属 **NUMA 0**（说明文档「理想是分散在 2 个 NUMA 节点」在本机不成立）
  → 记录：本机为**单 NUMA**，跨卡往返不经 UPI/QPI（`SYS` 未出现）

## 6. 关键差异与判定（本机 vs 集群）

| 指标 | 集群 4×3090（文档 §0） | 本机 | 比值 |
|---|---|---|---|
| 单流 host-staged 饱和带宽 | 11.9 GB/s | **5.95 GB/s** | **0.50×** |
| bench_comm channel | 19.15 GB/s | **10.31 GB/s** | 0.54× |
| bench_comm p1-batched | 10.36 GB/s | **5.79 GB/s** | 0.56× |
| bench_comm ratio（机制） | 1.85x | **1.782x** | 0.96×（−3.7%） |
| 逐对 host-staged（2MB） | — | 5.74 GB/s | — |

- **根因**：`Host Max PCIe gen = 3`，而 RTX 3090 支持 gen4 → 本机链路是 **PCIe 3.0 x16**，
  与集群参考（数字反推为 **PCIe 4.0 x16**，单向峰值 ~2×）**恰好 2 倍差**。
- **判定（按说明文档 §2）**：
  - 第 1、2 关 **通过**（拓扑/无 P2P 前提成立，这正是在本机跑的前提条件）
  - 第 3 关 **几何带宽偏差 ≈50%，远超 20% 阈值** → **本机绝对数字不可与集群 2 卡主数字混用**
  - 但 **机制比值（channel/p1 = 1.78x，与 1.85x 差 3.7%）仍在容差内** → M1 机制证据本身成立
- **对 W3 的含意**：host-staged 带宽减半 ⇒ 通信相对更贵，C 相对 A/B 的**相对收益可能更大**，
  但**扩展效率曲线的绝对值**与 2 卡主数字不同口径，需单独标注硬件后使用。

## 7. 冒烟测试

| 用例 | 命令 | 结果 | 结论 |
|---|---|---|---|
| 2 卡 | `timeout 300 ./build/run_multigpu --gpus 0,1 --tasks 32768 --arrival steady --skew balanced` | A 390.15ms / B 461.27ms / C 318.85ms；C/A 1.22x C/B 1.45x；steals(B/C) 3190/21；imb 0.000→0.195→0.181 | ✅ 三模式全完成，无死锁 |
| 4 卡 | `timeout 600 ./build/run_multigpu --gpus 0,1,2,3 --tasks 65536 --arrival steady --skew imbalanced` | A 702.22ms(imb 1.380) / B 874.36ms(imb 0.122) / C 471.27ms(imb 0.036)；C/A 1.49x C/B 1.86x；steals(B/C) 42622/177 | ✅ 三模式全完成，无死锁、无 idle heartbeat 刷屏 |

- 4 卡偏斜档：静态划分 `imb=1.380`，C 仅用 **177 次批窃取**拉回 `0.036`，B 需 **42622 次单任务窃取**
  —— N 卡批粒度重分配优势在真机复现。
