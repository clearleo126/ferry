## 5. 关键交叉验证（PCIe 3.0 的独立证据）

| 量 | 集群 4×3090 | 本机 | 比值 |
|---|---|---|---|
| T_compute_alone（R5 三项之一） | 16.45 ms | **16.42–16.46 ms** | **1.00×（计算不受影响）** |
| T_comm_alone | 24.53 ms | **45.05–45.17 ms** | **1.84×（通信变慢）** |
| overlap ratio | 0.400 | **0.263–0.264** | 因 T_comm 变大而下降 |
| M1(P1) 端到端 | 1.85× | **1.89–1.90×** | 机制倍数保持 |
| bench_comm channel/p1 | 1.85× | **1.78×** | 机制倍数保持 |

> 结论：本机**计算项与集群逐位一致**（16.46 vs 16.45ms），**通信项慢 1.84×** ——
> 与拓扑验收里「单流 5.95 vs 11.9 = 0.50×」互为印证，**确认差异来自 PCIe 3.0 链路，而非代码或负载**。
> 机制倍数（1.89 vs 1.85）在两条链路上都成立 ⇒ **机制证据与硬件平台无关，绝对带宽数字才是平台相关的**。

## 10. A4 / W6 — B1 公平基线：D1(one-steal) / D2(steal-half)（4 卡，5 次）

**动机**（实验设计 W6）：C/B 差距同时混淆了「批化执行 + 异步流水」与「窃取粒度」三件事，
不能直接归因"批窃取优越"；StealHalf（Hendler-Shavit, SPAA'02）亦须对照。
**D1/D2 与 C 完全同引擎**（自适应批 + 双流流水 + 在途窗口 + 事件收割，同一 submit 路径），
唯一变量 = 窃取请求量：`D1 = 请求 1`（B 的粒度，但无逐批 sync）/ `D2 = 请求 SIZE_MAX`（偷 victim 一半）/ `C = 请求消费批`。

### 10.2 归因拆解（偏斜三档，makespan 均值）

| condition | B | D1 | C | **B→D1 引擎** | **D1→C 批窃取** | steals B → D1 → C |
|---|---|---|---|---|---|---|
| steady / imbalanced | 442.36 | 282.14 | 250.79 | **1.57×** | **1.12×** | 21348 → 17549 → 101 |
| bursty / imbalanced | 441.31 | 284.10 | 249.18 | **1.55×** | **1.14×** | 21274 → 17549 → 98 |
| skewed / imbalanced | 432.88 | 280.80 | 251.22 | **1.54×** | **1.12×** | 21186 → 17318 → 99 |

- **引擎贡献（B→D1）≈ 1.54–1.57×**：批执行 + 双流流水 + 异步（无逐批 sync）之和
- **批窃取净贡献（D1→C）≈ 1.12–1.14×**，同时 steals **↓ ≈175×**（~17.4K → ~100）
- **D2（偷一半）≈ C（0.996–1.002）→ 无额外收益**，回应 StealHalf(SPAA'02) 的"多偷更好"
- 平衡档 A 本身均衡，D1 几乎不窃取（276–305 次），C/D1 仅 1.02–1.08
- 与 9bd0a3e 首批冒烟（GPU2↔3 单次：引擎 1.81× + 粒度 1.13×）方向一致；4 卡重复把引擎项
  下修到 ~1.55×（卡多时 baseline-A 的 bulk 更占便宜），粒度项稳定在 ~1.13×

### 10.4 口径建议（对齐实验设计 W6「诚实预期」）

- 论文不要把 C/B 笼统写成"批窃取 2×"，应拆为
  **引擎 ≈1.55× + 批窃取粒度 ≈1.13× + 窃取次数 175×↓**；
- C/A 偏斜档 1.47–1.55×，其中 D2 已 ≈C，故 C/A 优势主要来自引擎而非窃取粒度。
