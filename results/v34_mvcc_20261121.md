# v34 MVCC 握手（乐观快照）：结题（预注册见 `v34_mvcc_prereg_20261121.md`）

日期：2026-11-21；平台：本机 4×3090 独占；48/48 格（`{bal,full} × mvcc{0,1} × n=12`，
同 rep 相邻交错、顺序按 rep 奇偶翻转）。日志 `/data1/ferry_artifacts/v34_mvcc/`。

## 0. 结论（先写死）

1. **机制成立（M1）**：`[steal-seg]` 的 `tick` 份额 **44.2% → 0.0%**；
   每次运行的 `steal_ms` 中位 **1141 → 436 ms（−62%）**；在途重叠窃取中位 40 次/运行
   （证明真的与 victim 的在途 tick 重叠，不是靠"没偷"取巧）。
2. **makespan 收益不成立（M2）**：full 场景配对差
   `[-128,-1169,-444,-501,14,-46,63,221,1081,1032,588,976]`，
   中位 **+39 ms**、均值 +141、5/12 为负、95% CI **[−295,+577]** 跨 0。
3. **treatment 改变了轨迹（M3 不成立）**：窃取次数 **26 → 44（+64%）**、
   迁移字节 **409 → 560 MB（+37%）**、计价字节 **4341 → 5778 MB（+33%）**、
   refill **+4.4%**。握手便宜了，策略立刻把它花在更多迁移上。
4. **单位迁移成本确实下降**：full **7.06 → 5.21 ms/MB（−26%）**；
   bal **5.20 → 4.47 ms/MB（−14%）**。⇒ 握手优化是真的，只是被量放大吃掉了。
5. **均衡场景无伤害（M5 成立）**：bal ΔE 中位 **−100 ms（−3.6% vs RR）**，8/12 为负；
   但同为"更多迁移"（497→565 MB）。
6. **正确性（M4 的结构部分）成立**：48/48 格 `[audit] step_mismatch` 均为空
   （每个请求执行步数 == 其长度）；无挂起、无超时。

一句话：**静默期可以安全删掉（机制成立、成本真降），但它不是 makespan 的约束——
因为偷得越便宜，门控就越频繁地搬；在慢卡 regime 下额外的迁移量会把省下的时间再吃掉。**

## 3. 机制读数

### 3.1 静默期确实是"真空转"
`tick=0.1ms`（原 44%）。同时 `lock` 从 22% 掉到 0——因为 mvcc 下不再需要
"先等本卡出 tick 再通知 victim"，全局 `steal_lock_` 的排队也随之消失。
`net`（vchan 计价等待）升到 43–54%，成为 steal 的主要成本，这说明剩下的
时间已经全是**真实搬运**，不再是协调。

### 3.2 省下的时间被策略花掉了（关键）
握手让单次窃取从 19.0ms 降到 11.3ms（full，`ms/att`），于是**同样的门控在单位时间内
做了 1.6 倍的窃取**。结果：
- 迁移字节 +37%、计价字节 +33%（home 搬运跟着放大）；
- refill +4.4%（乐观快照漏块 + 更多迁移带来的冷启动）；
- 单位迁移成本 −26%（真实改善），但总 makespan 中性偏坏。

⇒ 与 §33/§35 同一条主线：**迁移系统的瓶颈不在"搬得多快"，而在"该不该搬"。**
本轮把"搬得多快"这一项实测提高了 26%，makespan 不动——这是对 §35 结论的
独立复现，且这次是从**执行侧**而不是字节侧。

### 3.3 后段反转（必须写进限制）
last6 的 ΔE 全部为正（+63…+1081）。可观测的候选解释：
1. 迁移量更大（+37%）在慢卡 regime 下边际更贵（每多搬 1MB 挤占回填通道）；
2. 更便宜的窃取让"抢回来又被抢走"的往返更容易发生（本轮的 `migr/steal`
   从 15.7MB/次降到 12.7MB/次，方向上支持"更碎、更频繁"）；
3. 机器热状态随时间变化，且**treatment 对热状态更敏感**（它做更多工作）。
本轮**没有能分离这三者的控制臂**（见 §4），所以只能报"后段反转"这个事实，
不主张因果。

### 3.4 锁税与正确性
- 新二进制在 `mvcc=0` 下不加任何锁（`kv_lk` 返回 nullptr），历史路径逐位不变；
  full/base 中位 2887ms 落在 §35 同格（2949ms，5 次）的噪声带内。
- 结构审计：`step_of(r) == len[r]` 对 48×48 个请求全部成立。
  实现过程中修掉两个真实缺陷（跳步、位图自锁），见预注册 §2.1；
  作废的 v1 批次日志保留在 `_invalid_v1/`。

## 4. 边界与未做

- **单 trace、单机、s96/ln32、B=25**；`full` 只测 g=1 全程 ×3。
- **缺"冻结策略"控制臂**：本轮 treatment 同时改变了握手与迁移次数
  （M3 已量化），因此 M2 测的是**复合效应**，不是"纯握手"。
  要隔离，需要在 mvcc 臂上把窃取次数钉在基线水平（例如按 `steal_ms` 预算配额）。
- 后段反转的三种解释未分离（§3.3）。
- 未做差量补丁（mvcc=2）：乐观快照的漏块代价实测只体现在 refill +4.4%，
  小于迁移量放大的影响，优先级低于"配额/体积感知的门控"。
- p99 无系统变化；不作尾延迟主张。

## 5. 下一步（由本轮结果直接推出）

1. **体积感知门控**：在 `cost_filter` 里加一项"边际迁移成本"（当前在途迁移
   字节 + 本批字节 > 预算 ⇒ 拒绝），把便宜握手换来的次数增长**锁住**。
   若成立，预期是"握手 +37% 迁移量 → 回落到基线量级，同时保留 −62% 的
   steal_ms"，这才是可写的正结果。
2. 差量补丁（mvcc=2）留到 1 之后再评估。
