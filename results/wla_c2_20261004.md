## 2. ⚠️ 核心结论：C/RR 反转（1.17 → 0.73–0.82）

**基线矩阵（C2 关）C/RR = 1.17±0.10（RR 支配）；本矩阵（C2 开）四格
全部反转为 0.73–0.82±，28 次中 27 次 C 快于 RR**（唯一离群
steady/bal r7 = 1.052）。机理 = 前缀共享使 refill 位置相关：

- refill：RR 恒 **1256.5±0.0 MB**（trace 全价，位置无关）；C 660–733
  （组局部性命中）、B 583–674、E 620–675、LLX 1239–1250（**LLX 的
  全局重平衡把请求搬离 home → 前缀缓存全丢**，虽迁移量仅 116–158MB）。
- 忽略局部性的冷启动代价 = RR−C **+517–599 MB（×1.61–2.03，均值
  ≈×1.75）**；hit_rate 0.921（C2 关时 0.865）。
- **迁移量-性能单调性反转**（对照基线 §3）：C2 关时 RR 0 < LLX 171 <
  E 514 < C 727 MB，makespan 同向上升（迁移=纯成本）；C2 开时迁移最多
  的 C（415–765MB）反超零迁移 RR，迁移从成本项变成收益项。

## 3. 次级观察

- **E 在局部性 regime 成为四格最优**（E/C 0.90–0.98）：costaware 的
  值过滤（只迁高剩余工作请求）→ migr 比 C 少 30–60%（161–528 vs
  415–765MB）、refill 与 C 持平或更低 → "既省迁移又保亲和"。E refused
  5.9–10.1 次证明门控真实起作用。**论文主推模式应从 C 转向 E**（C 作
  结构基线、E 作最优配置）。
- **LLX 输在 refill 而非迁移**：migr 仅 C 的 20–30% 但 makespan 慢
  19–41%——全局周期重平衡"无局部性意识"的代价直接可见，正好补上
  v8 基线里 LLX≈C 的解释（那是因为当时 refill 位置无关，谁都没收益）。
- **B（dest 亲和分发、零迁移）refill 最低但 makespan 中游**：亲和收益
  真实存在，但不迁移就无法纠失衡（imb 档 B 慢于 C/E 8–28%）。
- A/RR 4.68–8.33：局部性 regime 下"亲和+重分配"缺一不可（只亲和=B，
  只均匀=RR，都不够）。
