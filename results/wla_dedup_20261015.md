## 1. 背景：F0-a 审计的三个发现（2026-10-15，只读遥测引入后首次冒烟即现形）

1. **组 LRU 并发修改竞态（正确性，C2 regime 特有）**：`steal_from` 在释放
   `mtx_` 后无锁枚举 `lru_set_[v][q]` 建 idx 表并 `kv_handoff` 拷贝容器；
   victim 被唤醒后可立即 `tick_begin` → 留在 victim 的**同组剩余成员**
   `kv_touch` 插入同一 `unordered_set`（窃取批拆散组即触发）。
   证据：同一函数内两个语义相同的枚举数出不同的数——grp4 下 live_slots ≠
   审计 total（C 17180 vs 17166、E 3705 vs 3604），grp1（组=请求，拆散在
   结构上不可能）逐位相等（16877=16877）= 判别性对照。后果三档：
   ① 迭代/拷贝期间并发 insert = UB（112 跑旧矩阵未崩属集合小、rehash 少）；
   ② idx 建表与 handoff 拷贝之间的插入 → 消费卡镜像含**未传输块** → 后续
   "命中"读旧槽字节（内容级，时序无感）——正是 16.6 F0 规格预判的
   "同组并发读者"缺陷类；
   ③ v8 的 20/20 自检（refill==trace）在 grp1 跑，对该缺陷**免疫**。
   LLX 另有独立暴露：重平衡线程写 `[dst][q]` 无 `in_tick_[dst]` 检查。
2. **delta 批内槽位冗余（幂等浪费）**：同批同组请求重复枚举同一组集合 +
   block%hot 槽位别名 → 同一 offset 被传输多次（同源同目的，最终内容
   不变）。grp4 实测 dup：C 43.6%、E 40.7%（grp1 仅 8.3% = 纯别名）。
3. **full 组段冗余**：同批同组请求整段重复复制。grp4 实测 dup：C 38.5%、
   E 55.6%。

## 2. 系统改动（src/runtime/wla_multigpu.cuh + src/benches/run_wla_multigpu.cu）

**竞态修复**：
- 原 v-wait 合并为双侧出 tick 等待 `(in_tick_[v] || in_tick_[g])`（g 侧为
  LLX 补互斥；C/E 的 thief 即 g 执行线程，恒直通零成本）；
- 状态快照（idx 枚举 + kv_handoff + F0-a 审计）整体搬进 `mtx_` 临界区
  （双侧出 tick 后持锁直通：tick_begin 需 mtx_ → 双侧无法再进 tick）；
- 传输阶段（毫秒级 D2D）只消费快照（idx_all/chunk_ns/naive_offs），不再
  触碰 host LRU 容器。**idx 与 handoff 同临界区 ⇒ 消费卡镜像 == 实际传输
  集合**（"镜像含未传输块"语义裂缝同步闭合）。
- 时序影响（单跑对照，竞态修复自身）：grp4/delta C 312.9→302.7ms（噪声内）；
  LLX 因补 g 侧等待迁移时机后移（migr 240→120MB，行为变化，如实记录）。

**D2 第一步——批内去重（纯字节节省，决策语义不变）**：
- delta：快照后对 idx_all sort+unique（重复幂等：同源同目的同字节）；
  chunk 切分改按 staging 容量。E 的成本代理（kv_live 每请求口径）未改
  → 窃取决策不变，仅实际传输字节下降。
- full：同批同组段只复制首见组（sent_grp 集合）；grp1 时组=请求恒
  distinct，数值不变。
- delta-naive（ablation strawman）：**保留原始枚举不去重**（其语义 = 量化
  "逐槽 submit 实现缺陷"，含冗余字节）。
- F0-a 审计口径升级：total = 去重前条目数（= naive 实际发送），
  distinct = 去重后（= delta/full 实际传输）→ **dup% = 去重节省份额**。

## 6. 结论（写入论文的口径）

1. **F0-a 闭合（时序保真侧）**：WlA 迁移路径的 host 状态访问全部收进
   双侧出 tick 临界区；三条不变量 28/28 常驻可验。旧矩阵的时序结论
   （C/RR 反转、E 四格口径、delta 转正）在新实现下全部复现 ⇒ 此前
   数据不受竞态时序影响（内容级裂缝见第 7 条限制）。
2. **D2 第一步落地**：批内去重 = 零决策复杂度的纯字节节省（delta −39%、
   full −44% 实测迁移字节）；"E 等性能下 −65% 迁移"在两模式同享去重的
   公平对照下保持——**该 −65% 现在是内容选择 + 去重的联合收益，且对照
   两侧同享去重**，比旧口径更硬。
3. dup% 节省份额成为常设遥测（[F0-audit] 行），任何后续矩阵自带该列。

## 7. 限制与口径警告

- 本次矩阵数 = **竞态修复 + 去重**两项改动的联合效果，不可单独归因于去重
  （单跑对照显示竞态修复自身对 C/E 时序无系统影响，可作弱分离证据）。
- F0-b（内容保真度）仍未做：同组同 block_id = 同内容仍是声明语义
  （hash 前缀缓存口径），槽位别名下"命中读到的字节"未做内容校验。
  竞态修复消除了"镜像含未传输块"，但**未**消除别名覆盖的内容混合。
- E 的成本代理（每请求 kv_live）未随去重更新 → E 决策偏保守（实际成本
  更低）；属于已登记的 margin 口径范畴，非新缺陷。
- delta-naive 保留冗余（strawman 语义）；引用其数字时须注明。
- 旧表 E/C 标签语义存在 E÷C/C÷E 混用风险；本文件一律 C÷E（>1 = E 快）。
